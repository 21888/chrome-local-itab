# Personal-card subscription startup isolation

The production dashboard initializer mounts Focus before Countdown and Scratchpad. A Focus backend subscription registration exception previously escaped from the default Controller constructor, before View construction, rejecting the dashboard initializer and preventing later personal-card mounts. Countdown registered asynchronously during init: its View consumed that rejection, allowing later cards to mount but leaving Countdown loading without recovery feedback.

Each affected Controller now catches registration failure, retains a private terminal failure guard, and exposes a dedicated reopen message. A failed instance cannot bypass the missing subscription through later reads or mutations. The card and Settings remain unavailable for editing and hide ineffective read retry. A fresh instance may register and read normally. The dashboard initializer, Store persistence, ordinary read-error retry, timer calculation and Scratchpad autosave are unchanged; no blanket dashboard catch suppresses unrelated errors.

`tests/dashboard-personal-subscription-failure.test.js` executes the real `initializeDashboard` from newtab.js, actual Focus/Countdown/Scratchpad mount functions with their default Controllers, real Stores and Views, and the real quote renderer. A synthetic Workspace backend factory supplies independent raw states and a throwing subscription registration. Non-personal theme/background/module-visibility/information-card functions are bounded fixture substitutions; tasks, search and shortcuts are not mounted by this fixture. This is not a complete browser/extension startup test.

The initial unchanged-source negative rejects the Focus dashboard call with the backend error and finds no Countdown error state. Both language regressions after the fix confirm that all three real personal-card Views exist, the unrelated Scratchpad displays its original nonempty note, and the quote is rendered. Failed-module cards and Settings show the localized reopen message, keep controls disabled and hide retry. The failed module has zero reads; complete backend raw data and total write count remain unchanged. Even after backend recovery, direct reads/mutations on the failed instance reject; a new instance registers and reads without writes.

The related Focus and Countdown controller/View suites pass with the new integration cases (106 total). An intermediate fixture assertion selected Countdown's earlier status-like element instead of its actual main Settings status; it was corrected to inspect the View-owned status/retry controls, without changing production behavior to satisfy the fixture. Initial negative and intermediate logs are retained separately. This evidence uses synthetic DOM/storage and does not establish native event-registration failure, browser reopening, disk persistence, upgrade safety or historical incident attribution. No version, permission or Store submission change is included.
