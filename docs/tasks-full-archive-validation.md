# Import a full Tasks recovery archive

A valid Tasks export can contain eight previous local copies. The former importer always required an additional slot for the destination, even when that destination had no records, pin or history. It therefore rejected a full archive in a fresh browser profile.

The narrow exception applies only to explicit replacement into a destination with no task records, no pin and no recovery copies, when the imported copies exactly fill the existing eight-copy capacity. That case omits the redundant empty snapshot. It preserves every imported copy and destination visibility; task identities/order/states/pin remain, while live record versions are regenerated as before. Completed and removed destination tasks are real data and do not qualify. Existing history is never evicted. Recover/restore behavior is unchanged.

Import review wording now describes the exception and uses a neutral replacement action. The integrated suite passes 397 Node tests and 19 Python packaging tests. New regressions reproduce the old refusal, verify actual export/parse/replace roundtrips and retained history, and cover visibility, nonempty destinations, stale review, conflicting recovery IDs, write/readback failures and privacy exclusions. Independent probes additionally cover mixed states, full-capacity local recovery and simultaneous review rejection.

Native validation uses a synthetic archive generated by the actual Store.export() after supported operations, SHA256 `2a6d4652c80cb4981f3cd6247dc54bb2688bf3354d68123d88b55b5e0281a6bd`. In an empty owned cloud Chrome profile, the actual review displayed current counts 0/0/0/0 and incoming counts 2 active, 1 completed, 1 removed and 8 previous copies, with the truthful replacement explanation.
