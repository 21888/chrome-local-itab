# Scratchpad text copies

Scratchpad is optional, plain text and saved only in this browser profile on this device. Settings exports, browser Sync and Drive backups exclude it. Removing the extension or clearing browser data can erase it.

**Export text** downloads the current draft, including unsaved or conflicted text. Keep each draft you need. It remains available during import preview and save recovery.

**Import text** accepts one local UTF-8 `.txt` file, at most 128 KiB and 32,000 Unicode characters. Invalid UTF-8, larger files and read failures leave saved text untouched. Whitespace, Unicode, emoji, line endings and a literal leading BOM are preserved. Text is never interpreted as HTML.

Import is available only after the visible note is loaded and settled, with no unsaved draft or conflict. Selecting a file only opens an inline preview with its filename, character count and byte count. Export a copy of the old text first if needed. **Replace Scratchpad text** replaces the entire note. Select **Keep saved text and append this file** to preview the saved note followed by the file, then confirm **Append to Scratchpad**. A single LF line break is added only when both texts are nonempty and neither adjoining edge already has CR or LF. Existing whitespace, BOMs and line endings are untouched. The preview and counts describe the complete resulting note; combined text must fit the same limits. If it is too long, nothing is saved: shorten the file or turn off append to preview replacement. Each new file selection starts in replacement mode. **Cancel** or Escape dismisses without writing. Focus starts on Cancel and returns to Import on cancellation, or to the editor after confirmed import.

Editing, IME composition, a refreshed/changed saved state, a load error or closing the card invalidates the preview. Choose the file again against the latest saved note. Both import modes use the existing revision check: another tab cannot silently be overwritten. If saving fails, the imported draft stays in the editor with Retry and Export. Resolve any conflict explicitly. “Saved on this device” requires verified storage readback.

No new storage keys, permissions, network calls, file watching or import history are used. Keep your TXT backup somewhere safe; it can contain private text.

## Find text in this editor

Open **Find text**, enter an exact single-line query, then select **Previous match**, **Next match**, or press Enter in the query field. Search is case-sensitive: spaces and punctuation count, with no trimming, Unicode normalization or regular expressions. Complete Unicode characters, including emoji, are supported. An empty query disables navigation. The first Next starts at the beginning; the first Previous starts at the end. After a successful selection, the existing feedback shows **Match n of m**, counting overlapping matches in the current editor text. The first Next selects 1 of m; the first Previous selects m of m without a wrap notice. Further steps report when they wrap around, including a repeat when there is only one match. A missing match leaves the editor's selection unchanged and clears any old count.

Only the current page's main editor text is searched, including unsaved, conflicted, saving, failed and over-limit drafts. The 32,000-character limit is for saving; it does not truncate Find. Saved-conflict text, import previews and other workspaces are excluded. Editing the query or changing the editor text clears old results without moving focus. Typing a query does not count matches; counts are computed only for explicit navigation and shown after selection succeeds. An invalid query or failed selection cannot leave an old count. Choosing a match focuses the editor and sets its selection; native Chrome scrolling/selection painting has not yet been visually verified. Find does not edit or save text, trigger Retry, resolve conflicts or change import previews. Save errors remain separate from Find feedback.

Find does not intercept browser Ctrl/Cmd+F. Normal editing Enter is unchanged. Holding the Enter used to select a match does not insert repeated newlines after focus moves into the editor; release it before typing a new Enter. This guard is covered by DOM event-flow tests, not a physical-keyboard reproduction. Navigation is ignored during IME composition, before loading, or while the page/card is hidden, detached or inert. Closing Find clears its query and feedback, returning focus to Find text only if focus was still inside the panel. Hiding or destroying the card clears Find without moving focus. Hiding the page clears its match feedback; returning does not automatically search again. Find has no persistent query history, background index, stored match list, network request or storage write. Focused DOM-model tests cover offsets, matching, selection failures and lifecycle guards; they do not replace native keyboard, IME, narrow-screen or scrolling checks.
