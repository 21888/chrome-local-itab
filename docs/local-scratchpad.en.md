# Scratchpad text copies

Scratchpad is optional, plain text and saved only in this browser profile on this device. Settings exports, browser Sync and Drive backups exclude it. Removing the extension or clearing browser data can erase it.

**Export text** downloads the current draft, including unsaved or conflicted text. Keep each draft you need. It remains available during import preview and save recovery.

**Import text** accepts one local UTF-8 `.txt` file, at most 128 KiB and 32,000 Unicode characters. Invalid UTF-8, larger files and read failures leave saved text untouched. Whitespace, Unicode, emoji, line endings and a literal leading BOM are preserved. Text is never interpreted as HTML.

Import is available only after the visible note is loaded and settled, with no unsaved draft or conflict. Selecting a file only opens an inline preview with its filename, character count and byte count. Export a copy of the old text first if needed. **Replace Scratchpad text** replaces the entire note. Select **Keep saved text and append this file** to preview the saved note followed by the file, then confirm **Append to Scratchpad**. A single LF line break is added only when both texts are nonempty and neither adjoining edge already has CR or LF. Existing whitespace, BOMs and line endings are untouched. The preview and counts describe the complete resulting note; combined text must fit the same limits. If it is too long, nothing is saved: shorten the file or turn off append to preview replacement. Each new file selection starts in replacement mode. **Cancel** or Escape dismisses without writing. Focus starts on Cancel and returns to Import on cancellation, or to the editor after confirmed import.

Editing, IME composition, a refreshed/changed saved state, a load error or closing the card invalidates the preview. Choose the file again against the latest saved note. Both import modes use the existing revision check: another tab cannot silently be overwritten. If saving fails, the imported draft stays in the editor with Retry and Export. Resolve any conflict explicitly. “Saved on this device” requires verified storage readback.

No new storage keys, permissions, network calls, file watching or import history are used. Keep your TXT backup somewhere safe; it can contain private text.

## Copy selected text

Select text in the main editor, then choose **Copy selected text**, beside **Copy current text**. The copied string is exactly the editor's current UTF-16 selection slice: leading/trailing spaces, tabs, BOM, emoji, combining marks, multiple lines and literal markup stay intact. Native textareas normalize CRLF and CR to LF, so selection offsets and copied line endings follow that DOM value. Full-text copying continues to use the original controller draft.

An empty, invalid, out-of-range or split-surrogate selection leaves the clipboard unchanged and shows guidance. Only the selected slice must contain complete Unicode: malformed text outside it and a selection exceeding save limits do not prevent copying. A previously loaded retained draft remains eligible while saving, after a read/save failure, in a conflict or beyond save limits. Copying does not save, normalize or edit the note, resolve conflicts, change Find/import state, or programmatically move focus, caret or selection direction.

The two copy buttons share this view's single pending system write and dedicated status. Selection changes, edits, hidden/detached/replaced controls, a newer mount or an unavailable workspace retire stale selection feedback. An already-issued write may still finish; invalidating feedback does not unlock it early. Failure leaves the original selection available and offers explicit retry. There is no clipboard read, permission pre-query, legacy fallback or automatic retry. The operating system and other software may retain or sync clipboard contents.

[Selection-copy model evidence and native limits](scratchpad-copy-selection-validation.md). This feature has not been checked against an actual OS clipboard, native browser activation/keyboard/IME, narrow-screen layout or assistive technology.

## Copy the current full text

Choose **Copy current text** to send the main editor's entire current draft to the system clipboard, including unsaved, saving, conflicted, save-failed and over-limit text. It uses the controller's original draft, including CRLF, whitespace, BOMs, emoji and literal markup; it does not copy the separate latest-saved preview or import preview, truncate text, save it or resolve a conflict. Empty text leaves the clipboard unchanged. Incomplete Unicode characters must be corrected before copying. A loaded retained draft remains copyable after a read failure, even when editing is read-only.

The native button starts a clipboard write directly from your click. A separate polite status reports copying, success or failure; the save warning stays intact and focus/selection are not moved. If the browser denies copying or the API is unavailable, select the text to copy manually or export it. No permission request, clipboard read, legacy copy fallback, new storage key or network request is added. The system clipboard can be accessed by other apps and may participate in your OS clipboard history or sync; use it with care for private text.

Only one clipboard write can be pending for this card. Editing (even returning to the same text), IME, hiding the page/card, detaching it, page departure or destroying the view retires the old feedback. Workspace identity and availability are checked on a new copy, a controller render and pending write settlement. An unavailable or changed workspace blocks the new write or pending receipt at those checks. A workspace-only notification, without a card render or lifecycle event, does not immediately clear an already settled success message. An already submitted system write cannot be recalled, so a new copy waits until it settles. Reopening the card does not automatically copy again. A normal save of the same draft can finish while copying without incorrectly expiring the receipt. Copy is ignored before loading, during IME, or while the page/card is hidden, inert, detached or its workspace is unavailable. Copy success means that the browser's write promise resolved for the still-current draft; it does not mean the note was saved.

[Copy-current-text model validation and remaining native checks](scratchpad-copy-text-validation.md). Actual OS clipboard contents and line-ending behavior, browser activation/denial, native keyboard and IME, narrow-screen layout and screen-reader announcements have not yet been verified for this feature.

## Find text in this editor

Open **Find text**, enter an exact single-line query, then select **Previous match**, **Next match**, or press Enter in the query field. Search is case-sensitive: spaces and punctuation count, with no trimming, Unicode normalization or regular expressions. Complete Unicode characters, including emoji, are supported. An empty query disables navigation. The first Next starts at the beginning; the first Previous starts at the end. After a successful selection, the existing feedback shows **Match n of m**, counting overlapping matches in the current editor text. The first Next selects 1 of m; the first Previous selects m of m without a wrap notice. Further steps report when they wrap around, including a repeat when there is only one match. A missing match leaves the editor's selection unchanged and clears any old count.

The main toolbar’s **Find selected text** button sits next to Find text. Select complete, single-line text in the main editor, then activate it to open Find, replace the previous query with that exact selection and focus the query field. Case, leading/trailing spaces, emoji, combining characters and literal symbols are preserved. The editor need not still have focus. It reads the main editor’s current DOM text and selection at activation, never the saved preview, page selection or an earlier selection. The ordinary Find text entry does not prefill the query.

Prefilling does not scan, count or navigate. It clears the old match feedback and held-Enter state. Use Previous/Next, or release the activation key and press a fresh Enter in the query field, to navigate. Empty, out-of-range, CR/LF-containing or incomplete-Unicode selections leave the old query intact and open the existing panel with guidance to select complete single-line text. The editor’s text, selection direction, save status, warnings, conflicts and import preview stay unchanged, and the clipboard is not accessed. Loaded retained read-only drafts and complete selections beyond the save limit are supported. If focus handlers change the text, selection, query or current view, the earlier selection is not written over those changes.

[Selected-text Find model validation and native limits](scratchpad-find-selection-validation.md). Native Enter/Space activation, pointer and backward selection, IME, Chrome selection painting, layout and assistive technology still require browser verification.

Only the current page's main editor text is searched, including unsaved, conflicted, saving, failed and over-limit drafts. The 32,000-character limit is for saving; it does not truncate Find. Saved-conflict text, import previews and other workspaces are excluded. Editing the query or changing the editor text clears old results without moving focus. Typing a query does not count matches; counts are computed only for explicit navigation and shown after selection succeeds. An invalid query or failed selection cannot leave an old count. Choosing a match focuses the editor and sets its selection; native Chrome scrolling/selection painting has not yet been visually verified. Find does not edit or save text, trigger Retry, resolve conflicts or change import previews. Save errors remain separate from Find feedback.

Find does not intercept browser Ctrl/Cmd+F. Normal editing Enter is unchanged. Holding the Enter used to select a match does not insert repeated newlines after focus moves into the editor; release it before typing a new Enter. This guard is covered by DOM event-flow tests, not a physical-keyboard reproduction. Navigation is ignored during IME composition, before loading, or while the page/card is hidden, detached or inert. Closing Find clears its query and feedback, returning focus to Find text only if focus was still inside the panel. Hiding or destroying the card clears Find without moving focus. Hiding the page clears its match feedback; returning does not automatically search again. Find has no persistent query history, background index, stored match list, network request or storage write. Focused DOM-model tests cover offsets, matching, selection failures and lifecycle guards; they do not replace native keyboard, IME, narrow-screen or scrolling checks.

[Match-position model validation and remaining native checks](scratchpad-match-position-validation.md). The new count and live-status announcements have not been verified in native Chrome or with assistive technology.
