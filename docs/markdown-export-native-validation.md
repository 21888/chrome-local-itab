## Prompt export feedback and unsaved-work warning — 2026-10-28

A new bounded regression found that exporting saved Prompt B while Prompt A had an unsaved draft replaced the page's existing “Save them before leaving” warning with either “Download requested” or the export failure message. This was a feedback loss, not an observed draft deletion or historical upgrade-incident cause. Both outcomes were reproduced through the actual Prompt Store, Controller and View with a synthetic DOM/Blob boundary; the original negative log is retained locally in `evidence/markdown-export-feedback/baseline.log`.

Prompt Markdown outcomes now use a separate polite live-status region. They do not modify the Controller status or its draft warning. Cancel preserves the previous export outcome; an explicit successful retry replaces the export error and removes its error styling. Selecting another record or otherwise fully refreshing the detail clears the old export outcome, and the existing generation checks still reject late confirmation success/failure. The serializer, saved-record selection, privacy confirmation, download invocation and all storage operations are unchanged. Collection Markdown was not changed without a matching demonstrated defect.

Final targeted model coverage includes success/failure with another unsaved draft, the actual review dialog's failure → Cancel → explicit retry sequence, and late accepted/rejected confirmation after selection changes. Assertions preserve exact drafts, all stored library/recovery values and write count, while distinguishing zero from one download request. The old native reports above remain historical evidence, not proof of this new source. An anchor request is not verification that a browser completed a disk download. This change does not relax any installation, import, account or incident-release boundary.
