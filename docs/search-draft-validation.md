# Main-search draft ownership validation — 2026-10-09

Ordinary non-whitespace queries, direct-URL drafts, Unicode/IME drafts and calculator expressions now retain the search instance's reload ownership. A confirmed live window returned from an ordinary submission releases only the unchanged value/revision; null/noopener ambiguity, blocked/closed/throwing opens and missing custom engines conservatively retain the draft. Subsequent edits restore ownership. No persistence, extra navigation, provider or open-option changes were added.

The final aggregate suite passes 124 tests. Independent review reproduced original data loss and fixed behavior through the actual initializer, applied-Sync listener and lifecycle with a modeled reload. Coverage includes throwing window getters, synchronous edits during open, repeated submissions, editing back, programmatic changes, composition, unrelated pending owners, discard cancellation and detached remounts.

These are deterministic DOM-model checks. Native Chromium/IME/popup/live Sync behavior was not newly verified because the cloud test browser was unresponsive. A returning window handle establishes dispatch, not completion of loading a destination. The conservative null/noopener behavior is intentional.

A later native regression run on the exact published `7242483` runtime verified ordinary-input/calculator transitions in Chinese Clarity/light and English Graphite/dark, plus exact localhost URL routing. It did not trigger an actual applied-Sync reload, so the draft-preservation conclusion remains based on the deterministic listener/lifecycle tests above. Native IME composition is still unverified.

## Submission feedback and guarded keyboard retry — 2026-10-09

The main search now keeps a localized status region outside postprocessing and outside the result itself. Only a thrown `window.open` call reports failure; null, closed, unreadable or otherwise unconfirmed handles use neutral “unable to confirm” wording. A live handle clears the hint without claiming the destination loaded. The original draft remains available for a deliberate retry. Editing, changing engines, composition and the next submission clear obsolete feedback. No automatic retry, fallback navigation, new permission or persistent state was added.

Detached or replaced forms cannot navigate. Operation and edit revisions prevent a synchronous older submission from replacing a newer draft or status. Enter repeat/composition guards also cover the focused submit button. Explicit calculator expressions remain local, including invalid expressions and missing/throwing calculator helpers. The empty status region stays present through the existing visually-hidden style; it is not removed with display:none.

The combined candidate, including the published Finder shortcut, passes 215 Node tests and 19 Python packaging tests. Independent review additionally exercised 18 synchronous reentrant result combinations and two remount cases. Failure/unknown handles, held-repeat suppression, native IME and assistive-technology announcements are not claimed as native-browser verified.

Bounded native checks used official Chrome for Testing 155.0.8059.39 on cloud Linux, normal sandbox: English Graphite/dark at a 1188×848 native window and Chinese Clarity/light at 510×848. Real URL submissions opened a target tab and retained the source input without a success banner. The localhost destination refused the connection, so destination loading did not succeed. A normal query opened a tab but its final result page was not verified. Local expressions produced 14 and -5; two discrete Enter presses on the Chinese Calculate button stayed local. Finder slash still opened from the page and did not intercept search typing. No popup/security settings changed and no fault injection was used. A second URL Enter after focus transferred to the destination is explicitly not evidence for source-key-repeat suppression.
