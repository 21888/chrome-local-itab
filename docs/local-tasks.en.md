# Local Tasks

Enable **Tasks** under module visibility settings. It starts empty and is optional. Hiding the card keeps its contents.

- **Filter tasks** matches plain task text locally, ignoring case and outer spaces, across active, completed and removed tasks. All matching active tasks are shown; open **Completed** or **Removed** for their matching rows. **Clear filter** returns to your prior Show all/Show fewer view. Clear the filter before reordering tasks. The filter is not saved, does not search the web, and does not change task order, the pin, drafts or backups.
- Add a plain-text task with Enter, or use Shift+Enter for a new line.
- **Add multiple tasks** opens a separate plain-text editor. Every nonblank line becomes one task in its original order; spaces, bullet prefixes and duplicate lines are kept. **Review tasks** checks the full batch and shows a numbered preview, exact count and remaining record capacity. Only **Add reviewed tasks** writes, in one all-or-nothing operation. Editing or an observed list change requires another review. The existing pin, records, previous copies and settings are preserved.
- Preview and cancel write nothing. If confirmation fails after a possibly successful save, **Retry previous add** retries the same reviewed batch, even if you have typed a newer draft. That newer draft remains untouched and needs its own review. A later acknowledged mutation requires a fresh review rather than repeating the older operation. Closing a draft does not undo a save already in progress; unfinished input is page-local and is not saved when the dialog/page closes.
- Open **Completed**, then choose **Select completed tasks to reopen**. Its initially unselected candidates are exactly the completed rows displayed at opening, including the current text filter; active, removed and hidden completed rows are excluded. Review the full numbered originals and count before explicitly confirming one all-or-nothing save. Selection, review and cancel write nothing. Reopening preserves original text, stored list positions, record count, previous copies and **Next up**. It creates no new Undo/redo action; an unrelated existing Undo remains available while its records are unchanged.
- Reopening rechecks the reviewed list revision and every completed identity/version inside the existing write lock. Any mismatch stops the entire save. Selection changes and observed list updates require another review. An uncertain save keeps its exact original preview/command for explicit retry, even after checkbox changes or closing; later mutations or expired receipts stop that retry. [Verification scope and limits](tasks-batch-reopening-validation.md).
- **Select tasks to complete**, above the active list, opens an independent selection window containing exactly the active rows displayed at opening: the first four when collapsed, all when expanded, or all matching rows when filtered. Completed/removed rows and an otherwise invisible **Next up** task are not added. Nothing is initially selected. Select all listed tasks or choose/uncheck individual rows; duplicate text remains separate, and complete saved whitespace, line breaks, Chinese, emoji and literal HTML remain readable.
- **Review selected tasks** reads and checks the selected identities/versions without writing. Its numbered preview shows every original in display order, the count, and whether completion will clear **Next up**. Changing the selection or observing a newer list invalidates the preview. Only **Confirm completion of N tasks** writes: one locked all-or-nothing save, one revision and one receipt, followed by full readback. Any changed selected task or reviewed list revision stops the whole command before writing. Only a pin belonging to a selected task is cleared; unselected records, order, text and previous copies stay intact.
- If reading, writing or verifying leaves the save unconfirmed, explicitly **Retry completion of these N tasks**. The preview and retry retain the original immutable command and exact selection, even if you change the checkboxes. No automatic replay or partial-success claim is made. Closing the window cannot cancel a write already sent; its uncertain original remains available from the card's **Retry**, including after another page hides Tasks. This temporary visibility does not change the saved visibility preference. A later mutation or expired receipt stops the old retry for review rather than replaying it.
- **Undo completion of these N tasks** shares the single page-local Undo slot with ordinary completion/removal. Preview/cancel and unconfirmed saves do not replace the previous slot; only a current, fully confirmed batch does. One explicit Undo reopens every member together. If any member was edited, reopened or removed, no member is reopened by this Undo. Unrelated changes and a newer pin stay intact; the former pin is never restored. There is no Undo queue or batch redo, and reloading clears the slot. Completed records still occupy capacity: completion does not free any of the 500 total records. [Modeled verification and native-browser limits](tasks-batch-completion-validation.md).
- Complete or reopen a task. Open **Actions** to edit, pin one next action, move up/down, move to the list start, or remove it.
- **Move to list start** puts an active task first in one save, keeping every other active task in its relative order. The moved task appears in the collapsed four-row preview and keeps its position after reloading. This changes list order; **Pin next** chooses the separate **Next up** task. Moving a task does not change that pin, task text, completion state or previous copies. The action is unavailable on the first active task or while filtering. If another page changes the target task or active order before the save, review the latest list before trying again.
- **Move to list end** moves an active task to the last position in one save, preserving every other active task’s relative order, all completed/removed slots, task text and dates, previous copies and **Next up**. The new order survives reload. The last active task and filtered lists cannot use it. Moving a task out of the collapsed four-row preview leaves the list collapsed and returns its own lost focus to quick entry; when still visible, focus falls back to that task’s **Actions** summary. Newer draft, search or editor focus is preserved. Another page changing the target or active order before the save blocks the whole move; unrelated edits and newer pins are kept. [Validation and native-browser limits](tasks-move-last-validation.md).
- **New task from text**, beside **Copy text** in all three task states, opens an independent, editable snapshot of that row's saved text. Opening, typing and canceling perform no task-storage write and do not use the clipboard. Only **Add** appends one new active task in the current workspace. The original record, completion/removal state, order, pin, previous copies, Undo, quick-entry draft and filter stay unchanged. Later source edits do not rewrite this draft or introduce a source-version conflict.
- Multiple lines remain one task; Enter in this editor inserts a line break. Spaces, literal HTML, Chinese and emoji are preserved. With no actual input edit, Add uses the original saved string, including CRLF/CR line endings. After an input edit, Add uses the textarea value, whose browser contract normalizes CRLF/CR to LF. Existing 500-record, 1,000-Unicode-character and 2 MiB limits still apply; a refusal keeps the draft and never truncates or removes records.
- If this Add cannot be confirmed because of a read/write/verification failure, **Retry previous add** displays and retries the exact original text and operation, even after new input, an ABA edit or an IME composition. Ordinary Add stays blocked until that attempt is resolved. A confirmed older result cannot close a newer draft; another task requires a separate explicit Add. A subsequent confirmed mutation makes an old receipt retry stop for review under the existing store rules. This does not extend the store's bounded 128-receipt history or promise indefinite deduplication after receipts age out.
- The new draft keeps departure/reload protection and remains reachable if another page hides Tasks. Workspace departure, retirement or suspension blocks new submissions. Canceling cannot cancel a write already sent; late results cannot clear a different draft or claim external focus. Drafts are page-local, are not included in backup, and are not automatically added by **Save drafts**. Closing returns focus to the current source row's button or quick entry only while the dialog still owns focus. [Modeled validation and unverified native behavior](tasks-reuse-draft-validation.md).
- **Copy text** copies only the saved text currently displayed in that row. It is available for active, completed and removed tasks (under **Actions** for the first two). Spaces, line breaks, Chinese and emoji are preserved exactly, without dates, status, IDs, other tasks or unsaved editor drafts. Copy is unavailable during a save, after a task read/save error, with an editor/import review open, or while the page is hidden or departing. File import/export errors remain separate from copy feedback. Only one clipboard request runs at a time; after it settles, you can click again. Copy does not read or write task storage or send network requests. It uses the displayed saved version without querying updates from other pages that have not yet arrived.
- Copy feedback appears on its own row and never replaces save errors, Retry or Undo. If clipboard access is unavailable or blocked, select the original task text to copy manually; there is no automatic retry. Editing, removing, filtering, redrawing, hiding, leaving or opening an editor while a copy waits discards its later feedback and does not move focus. A system clipboard write already started cannot be recalled and may finish after you leave. Your operating system or other software may sync the clipboard; the extension does not control that behavior.
- **Copy visible tasks (N)**, just above the active list, copies a numbered plain-text snapshot of those active rows in their displayed order: the first four while collapsed, all active rows while expanded, or all matching active rows while filtering. Completed and removed rows are excluded even when their sections are open; **Next up** does not add another copy. Zero active matches disables the button. Each task keeps its exact saved spaces, line endings, duplicate text, emoji and literal HTML; only a `1. `-style prefix and a newline between tasks are added. IDs, dates, drafts and previous copies are excluded.
- **Copy visible completed tasks (N)** appears inside expanded **Completed** and copies all completed rows currently displayed by the filter, in their saved list order. It preserves each exact original and adds only numbered prefixes and separators, just like active bulk copy. It excludes active/removed tasks, drafts and metadata; no matches disables it. Completed, active and per-row copy use the same per-view pending-write lock. Folding/reopening Completed or opening the reopen-selection window while waiting invalidates old feedback but keeps that lock until the issued write settles. Repeated mounting of the same host reuses that view; there is no new cross-view/global clipboard lock. [Completed-copy checks and native limits](tasks-copy-completed-validation.md).
- **Copy visible removed tasks (N)** appears inside expanded **Removed** and copies every currently displayed removed row, including rows removed from Active or Completed, in saved list order. Filtering sets the scope; collapsing Removed blocks copying, and zero matches disables the button. Original spaces, line endings, Unicode, duplicates and literal markup are preserved exactly; only numbered prefixes and LF separators between tasks are added, with no extra final newline. Active/completed rows, removed-from labels, IDs, dates, drafts and previous copies are excluded. All three bulk controls and per-row copy share the existing per-view pending-write lock; stale sources, collapse/reopen, restore/re-remove, dialogs, errors and workspace changes discard old feedback without unlocking an issued system write early. Failure leaves the originals selectable for manual copying, with no automatic retry or focus change. [Removed-copy checks and native limits](tasks-copy-removed-validation.md).
- Bulk copy shares the same single in-flight clipboard request and safety checks as **Copy text**, without reading or writing task storage. Its separate feedback never replaces save errors, Retry or Undo. A filter/expand change, redraw, task change, editor/import review, hide, workspace departure or disposal while waiting discards the old feedback; the issued system write still holds the lock until it settles and cannot be recalled. A displayed success is a past result, not a live statement about your clipboard or later filter. On failure, select the visible original text to copy manually. [Modeled checks and native validation limits](tasks-copy-visible-validation.md).
- Use **Complete** beside **Next up** to finish the pinned task even when it is outside the four-row preview or current filter. The task text stays plain text; the button works with Enter or Space. Completing it clears the pin without choosing another task. If another page changes the pin or task first, the older action stops for review. Focus returns to Add a task only after a confirmed save, if you have not moved on.
- **Undo completion** reopens the last successfully completed task, including **Next up**, without restoring its old pin. It shares one page-local Undo slot with **Undo removal**: the latest completion or removal replaces the previous one, and reloading clears it. Later changes to that task prevent Undo; unrelated tasks and a newer pin stay unchanged. An uncertain save must be explicitly retried and confirmed first. **Completed** and **Removed** still let you reopen or restore items after reloading.
- **Task data** contains separate export, reviewed import, and previous local copies.
- For a previous local copy, **Review restore** now includes a collapsed **Contents of this local copy** section. Expand it to read every task in the copy’s saved order, including complete original text, Active/Completed/Removed state and its **Next up** marker. Duplicate text and line breaks are kept. **Removed from** records whether an individual removed task would return to Active or Completed; restoring the whole copy still leaves those tasks Removed. Empty copies are labeled explicitly.
- This read-only preview belongs to the selected replacement copy, not the current list. Opening, expanding, collapsing or canceling writes nothing. The preview and confirmation use the same saved revision; another page’s changes do not rewrite the open preview, and a stale confirmation stops for review. An uncertain save retries the same operation. File-import review is unchanged. [Modeled validation and native-browser limits](tasks-recovery-preview-validation.md).

Tasks stay in this extension's storage on this device. Settings exports, Chrome Sync and Drive backups do not contain tasks, completed items, removed items or their previous copies. Export tasks separately before moving devices or removing browser data. A downloaded file is not automatically a cloud backup. Uninstalling the extension or clearing its data can remove local tasks.

Import replaces the current task list and pin only after review. The preceding list remains in **Previous local copies**. Canceling or a failed replacement does not erase it. Settings reset/import/restore preserve task content. No permanent purge is offered in this version.

The local list holds up to 500 tasks, including completed/removed items, and each task can contain up to 1,000 Unicode characters. Up to 8 previous local copies are retained; the total task collection/file is capped at 2 MB. Reaching a limit blocks the new operation and keeps existing data. Exporting does not free space. At the copy limit, an existing copy can still be restored while retaining the current one.

When two pages edit the same task or a list changes during a reviewed import, the older action stops for review. Your current draft remains available. A save is confirmed only after local storage has been checked. If an uncertain save is followed by another change, retry asks you to review rather than assuming that the earlier result still exists.

There are no reminders, due dates, link previews, external accounts or automatic resets at midnight.

When a settings update needs to reload the page, an unfinished task draft, open editor/batch/selection/import review or pending save defers automatic reload. Use the page's Reload option when ready. Discarding drafts requires confirmation; an active save must finish first.

A backup containing all 8 previous copies can be imported into a destination with no task records, no pin and no previous copies. Only in this case, the redundant empty destination snapshot is omitted. All incoming copies are retained; visibility stays as configured on the destination, even if it was previously toggled. Active, completed or removed destination tasks, or any existing previous copies, retain the normal protection and capacity checks. Restoring an existing local copy is unchanged.
