# Privacy summary

Local iTab's core new tab page can work offline. Optional cloud features send data to Google or a user-selected model provider when used. Optional version checks contact GitHub only after a manual check or explicit opt-in.

- Configuration, shortcuts, categories, layout and theme settings, uploaded backgrounds, and local card content are primarily stored in `chrome.storage.local`. Website icons use local IndexedDB with a browser Cache API fallback; some interface state uses browser local storage.
- Tasks (including completed/removed items and previous local copies) and the Focus timer session are stored separately on this device. They are excluded from configuration exports, Chrome Sync and Drive snapshots; Tasks has its own explicit export/import. Tasks/Focus visibility and Focus durations are also device-only and excluded. Visibility settings for the weather, topic and movie cards remain ordinary configuration. Settings reset/import/restore preserve task content and the Focus session.
- Scratchpad is optional and off by default. Its plain text and visibility stay separately in this browser profile on this device, excluded from settings exports, Chrome Sync, Drive and configuration recovery snapshots. Settings import/reset/restore preserve it. Its explicit text export downloads the current draft, including unsaved text. Removing the extension or clearing browser data can erase the saved text.
- Countdown is optional and hidden by default. Its title, date and visibility are stored separately on this device, excluded from configuration exports, Sync, Drive and recovery snapshots. Settings reset/import/restore preserve it. Its own explicit text export can include an unsaved draft. It has no notifications or network requests.
- Calculator expressions beginning with `=`, results and errors remain in the current tab's memory. The calculator does not send them to a search provider or save a history in storage. This does not disable unrelated enabled network features.
- Browser-bookmark HTML files are read locally as text for preview and explicit additive import. The importer does not render or upload the source file or fetch icons. Applied links and categories become ordinary saved records: they enter subsequent configuration exports and Drive snapshots, may sync if Chrome Sync is already enabled, and normal dashboard icon behavior may contact Google if online icons are enabled and the current device has granted permission. Import does not change these preferences.
- The extension does not send search input while the user types. Submitting a search or opening a URL visits the selected provider or destination website.
- Online favicon fetching is off by default and requires the optional `https://www.google.com/*` host permission on the current device. When enabled and granted, it sends shortcut domain names to Google's favicon service.
- Version checks are manual by default. An explicit check, or an opted-in check while using a new-tab page (at most once per 24 hours), requests public release metadata from api.github.com. GitHub receives the IP address and ordinary connection details; no bookmarks, tasks, settings, current-version parameter, account, token or cookies are sent. Update preferences and cached metadata are device-only, excluded from exports/Sync/Drive, and cleared by Settings reset. Release-page links open only on an explicit click. The extension never installs files or reloads automatically. See [version checks](version-updates.md).
- Weather, topic, and movie cards display locally configured content, without remote feeds.
- Chrome Sync is off in the default configuration. When enabled, supported settings and shortcut data sync through the user's Chrome account, including later changes. Initialization checks for existing enabled sync data, which a new installation on the same account may automatically apply. Embedded backgrounds, posters, and shortcut icons are omitted or replaced with defaults in this sync payload.
- Google Drive backup requires separate Google authorization and stores JSON snapshots in the app-specific `appDataFolder`, using the `drive.appdata` scope. Snapshots include validated settings, shortcuts and URLs, categories, layout, theme and appearance, search and privacy preferences, local card content, and local background/poster/embedded shortcut images. They also include a generated device ID, the selected computer name, snapshot ID and time, extension and backup format versions, backup reason, and item counts. The separate favicon cache is not included; the snapshot's Chrome Sync state is replaced with disabled defaults.
- Connecting to Drive, listing or refreshing snapshots, uploading, downloading, restoring, deleting, and cleaning up older snapshots can contact Google APIs. There is no scheduled automatic Drive backup. After a restore is confirmed, the extension first attempts to upload the current configuration as a safety snapshot; if that fails, it asks whether to continue.
- The manifest declares `storage`, `unlimitedStorage`, `identity`, `contextMenus`, and host access to `https://www.googleapis.com/*`. Drive use is optional even though its Identity/API permissions are declared. Online favicon host access is separately optional.
- The extension does not include analytics, tracking scripts, ads, or remote content feeds. Local use needs no account; optional Chrome Sync and Google Drive use the user's Chrome or Google account.

- Explicit selected-text capture uses `contextMenus` only after a menu click. A bounded, expiring `chrome.storage.session` handoff opens an unsaved review draft; only explicit Save writes the collection. Source inclusion is unchecked by default, sanitized, and optional. Editable and private-window selections are excluded. There is no page scanning, model call or new network request. See [selection capture](selection-capture.md).

See the [privacy policy](../store-assets/privacy-policy.md) and [extension manifest](../manifest.json) for details.

- Optional direct-model requests send only the reviewed single prompt, model ID and any entered API key to the user-selected HTTPS Chat Completions endpoint after an explicit Send. The provider receives ordinary connection metadata and may charge. No ambient workspace, collection or browsing content is attached. Keys remain only in the dialog and are cleared after each request, endpoint edit or page departure; no key is saved in extension storage, Sync, backups or logs. Responses are saved only on explicit Save and then join the existing unencrypted collection/complete-backup formats; they may repeat private input. The optional `https://*/*` manifest declaration enables user-selected providers, but runtime permission requests name only the reviewed HTTPS hostname and port. Redirects are rejected and cookies/referrer omitted. See [reviewed model workflow](ai-model-workflow.md).

### Reviewed context Q&A

The new-tab AI context panel reads active global AI collection bodies and the pinned workspace's saved note only after it is opened. No source is preselected. Users choose and can edit exact outgoing excerpts, review the full request and endpoint, and explicitly send through the common model client. Excerpts and credentials are volatile; no new storage or backup boundary is introduced. Model responses are unverified literal text. Answer saving and reviewed task-list insertion are separate explicit actions into existing stores; neither generation nor cancellation writes content. See [context workflow and validation limits](ai-context-workflow.md).
