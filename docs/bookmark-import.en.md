# Import browser bookmarks from a local HTML file

Export bookmarks as an HTML file from Chrome, Edge or Firefox, then open **Settings → Data management → Import browser bookmarks**. Choose the exported file, review the counts, skip reasons and folder-to-category mapping, and explicitly choose **Apply**. Cancel or Escape discards the review without changing saved data. This is separate from **Import Settings**, which still restores a whole JSON backup.

Only HTTP(S) bookmarks are accepted. Existing URLs and repeated URLs in the file are skipped using canonical URL comparison; queries and fragments remain significant. Unsupported addresses, invalid titles and ambiguous duplicate HREF attributes are counted in the preview. Every source folder containing accepted direct bookmarks becomes a fresh flat category named with its complete folder path. Existing categories are never merged, even with matching names; repeated names receive a suffix. Root bookmarks use an Imported bookmarks category. Empty folders do not create categories.

The import is additive. Existing links, category IDs, order, free positions, settings, recovery copies, Tasks and Focus data are retained. New bookmarks use a local 🔗 glyph. Existing identity-bearing layouts receive fresh IDs for new links; legacy layouts remain legacy. Existing JSON exports and restores continue to include the newly saved links and categories normally.

The selected file is read locally as text. It is never rendered as HTML, uploaded by this importer or used to fetch icons. No browser-bookmarks permission, sign-in or new service is required. Review the current privacy disclosure: if Chrome Sync is already enabled, saved shortcuts may subsequently sync; if online website icons are already enabled, normal dashboard icon behavior may contact its provider. The importer does not change either setting or claim that the entire extension is offline. Changing either preference after preview requires a fresh preview.

Save category edits before importing. Preview does not write. Apply rechecks the current shortcuts, categories, layout identity and privacy choices inside the same local write lock; conflicting changes in another tab require a fresh preview. Position-only moves are retained. While Apply is saving, repeat clicks and cancellation are blocked. If a write or verification fails, the result may be uncertain: inspect a fresh preview or reload the saved state before retrying, rather than assuming nothing changed. No automatic retry or rollback occurs.

Files are limited to 10 MiB before reading. The parser accepts at most 10,000 encountered bookmarks, 2,000 new links, 200 new categories and 16 folder levels. Over-limit or structurally malformed exports reject as a whole; they are not silently truncated or repaired. Re-export from your browser when a file is rejected. Very large or corrupt existing local data also blocks migration safely; it is not normalized or discarded. The technical contract and precise limits are in [the parser guide](bookmark-import-parser.md).

The interface supports English and Simplified Chinese; Spanish documentation follows the project convention. Local fixture tests cover Chrome/Firefox/Edge export shapes. Native Chrome file-picker, keyboard, assistive technology and visual testing should be performed against the final unpacked extension before release.
