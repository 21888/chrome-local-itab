# Reviewed AI context and task drafts

Open **AI context Q&A** from the new-tab navigation. This workflow reuses the direct-model client's user-chosen HTTPS Chat Completions endpoint. It adds no provider, permission, storage key or backup module; the optional answer snapshot described below extends collection records with reviewed historical input.

## Workbench layout

On a wide screen, saved sources stay beside the question and local review. Source explanations and **Reload saved sources** are under **Source scope, limits and reload**. The question and **Review prompt locally** are available without opening connection settings. **Optional: call a model in this extension** contains endpoint, model, optional key, presets and the separate review/allow/send steps. Collapsing it preserves the draft and response; it does not send or save. Response actions are grouped with the response. Narrow screens stack the same controls in one column.

[Design reference and validation scope](ai-context-workbench-validation.md)

## What can be selected

- Active saved AI collection bodies, explicitly labeled **global collection**: these are existing cross-workspace library records, not workspace-local copies.
- The **saved workspace note** from the current pinned workspace session. Unsaved editor text is not included.
- No source is selected by default. No browsing, URL fetching, source-page scraping, clipboard reads, hidden collection annotations, archive/recovery records or other workspace notes are included.
- Selected excerpts remain temporary unless you explicitly save the optional question/source snapshot with an answer. Selecting one reveals its outgoing editable text; unchecking removes it. Editing an excerpt never edits the saved original. Saved sources changing later do not silently replace the exact reviewed excerpt.

## Review and copy a local prompt

**Review prompt locally** works with an empty endpoint and model. It shows the complete immutable prompt, including the mode instruction, question, selected edited excerpts, source IDs and labels. Hidden selected sources remain included; unchecked sources are excluded. The existing character limits apply without truncation. Inspect the full text for private information or secrets before pasting into any external service.

**Copy reviewed prompt** is a separate explicit action that copies only the current displayed local prompt. It adds no connection settings, API-key fields or authentication metadata. It does not contact a model, request endpoint access, write storage, or mark a response as saved. Local review never enables **Allow this endpoint** or **Send reviewed request**; sending still needs a separate valid HTTPS endpoint/model review. Reviewing locally clears any previous send authorization while keeping an existing answer and its original provenance.

Question, mode, connection or excerpt edits, selection changes, excerpt restoration, successful source reload, draft reset, response edits and closing invalidate the local ticket. Filters alone do not change its selected content. Pending operations and unresolved save/task operations block review and copy. Workspace validation runs before copying; late clipboard success or failure cannot update a newer review or closed panel. Clipboard failure offers manual selection without automatic retries. There is no clipboard read, automatic network request or persistent local-review record.

Synthetic controller and DOM-model tests cover these boundaries. Native browser clipboard behavior and visual acceptance were not tested for this change.

## Exact outbound review

Enter the endpoint, model, optional key and question; choose **Answer** or **Draft tasks for review**. **Review exact request** shows the complete endpoint URL, model and complete request text, including the mode instruction and JSON-encoded source IDs, labels and excerpts. IDs and labels are untrusted data, not executable instructions. Editing the question, target, mode or selected excerpts invalidates the review. The endpoint changes clear the key.

**Allow this endpoint** requests only the reviewed endpoint's origin using the common client permission contract. Approval does not send a request. **Send reviewed request** verifies access, then makes one foreground request with no automatic retry. Providers may charge. Stop aborts the request and restores editing even if a permission check, workspace check or transport callback has not returned. Late callbacks cannot send an old request or replace a newer result. The stopped status remains visible until the next explicit action. Stop cannot undo work or charges already incurred, does not retry automatically and does not cancel a local save already in progress. Responses are literal plain text, without HTML, Markdown links, code execution or verified-provenance styling. A model may invent source references: displayed claims and citations are not verified evidence.

**Search loaded source titles** filters only the titles already loaded into this panel, using trimmed, case-insensitive literal substring matching in the original order. It does not search excerpt text, tags, browser history or other workspaces, and does not read more data. The visible/total and selected/hidden-selected counts make hidden selections explicit: hiding a row never deselects it, resets its edited excerpt, changes the local budget, or removes it from the exact reviewed request or optional saved snapshot. Search leaves an existing review and response intact; actual source edits still invalidate review. **Clear title search** shows all rows and returns focus to the search input. **Cancel / clear draft** also clears the search, selections and excerpt edits. The query is session-only, is not itself an unsent draft, and is never saved or sent.

**Select visible unselected sources (N)** explicitly selects the entire unselected set in the current title-search AND selected-only view. It counts all existing selections, including hidden ones, toward the 12-excerpt cap. If the combined count exceeds 12, the action is disabled with the proposed total; it never takes only the first 12 or automatically deselects anything. In selected-only view there are no visible unselected sources. **Clear all selections** shows the total and hidden counts and unchecks every selected source, including hidden ones, while preserving the question, connection, answer title, search, selected-only toggle and edited excerpt text. Unselected edits still trigger the unsent-draft guard. **Deselect visible selected sources (N)** unchecks only sources matching the current title, scope and selected-only filters, preserving hidden selections and edited excerpts. Its target set is captured once and removal is not subject to the 12-source addition cap. All three actions invalidate review only on a real change, require a fresh exact-request review before sending, and are unavailable during pending operations or uncertain save/task retries. None of these actions reads additional sources, grants permission, sends or saves anything. Excerpt and complete-request character limits remain unchanged.

Limits: 12 excerpts, 16,000 UTF-16 units per excerpt, 4,000 for the question, 32,000 for the complete outgoing prompt or response. Requests exceeding any bound fail rather than silently truncate. The common client's bounded response parser, redirects/cookie restrictions, 60-second deadline and exact endpoint validation remain unchanged.

The panel shows live selected-count, selected-excerpt, question and complete serialized-prompt usage. Counts use the same UTF-16 lengths as strict validation (some emoji count as two), not token estimates, cost estimates or provider quotas. Instructions, source IDs/labels and JSON escaping count toward the prompt. Unselected excerpts do not count, even when their saved originals exceed the outgoing excerpt limit. Over-limit excerpts are identified next to their editable text; edit or deselect them yourself. Editing question, mode, selection or excerpts refreshes usage and invalidates the previous review. Cancel resets usage. There is no automatic truncation, deselection, permission request, send or save.

Invalid content can still have a measurable length; a count within bounds does not override validation. For malformed fields, more than 100 selected items, or more than 128,000 raw input units (question plus selected IDs, labels and text), the complete length is explicitly “not calculated” to bound local serialization work. Such input cannot be sent. Ordinary valid input, 16,001-character excerpts, two 16,000-character excerpts and JSON-escape expansion are measured exactly with the same prompt constructor used for packing.

## Saving answers and tasks

**Save answer to AI collection** explicitly adds the full reply to the existing global collection store. By default it saves no question or source snapshot and does not assert that model citations are verified. The answer may repeat private input and joins existing unencrypted local backups. No prompt-version reference is fabricated for a context question. Failed or uncertain save acknowledgement retains the immutable command for an explicit idempotent retry.

Task generation does not write anything. The response must be exactly a JSON object with one `tasks` array of 1–50 nonempty, single-line strings, each at most 1,000 UTF-16 units. Extra keys, objects, code fences, malformed JSON and multiline values fail closed. Users can edit the JSON; edits invalidate the task review. **Review extracted tasks** uses the existing task store's full-state batch validator and shows every exact task in order, including duplicates and literal markup. **Add these tasks** is the sole task write action, using the existing atomic batch path and existing capacities. Tasks are never executed.

The task-store API accepts an optional synchronous, ephemeral pre-write guard under its existing lock, after exact receipt recognition. Context confirmation uses it to reject a newer task revision or superseded draft. Existing task callers retain their behavior. A confirmed receipt retry never appends twice. A pristine revision conflict requires another review. Uncertain read/write/verify errors retain the identical command; if a later mutation makes its receipt conflict, the original identities stay fenced and a new review is blocked. The user is told the earlier tasks may already exist and to inspect Tasks before proceeding. All context stores use the existing workspace fence; a closed or replaced session cannot initiate a queued new save. A write already committed cannot be undone by closing.

## Dismissal and lifecycle

The new-tab dialog uses the existing focus trap and IME-aware Escape behavior. Closing restores the entry's focus. Unsaved responses prompt before discard; pending saves block dismissal. Cancel clears volatile source selection and draft text without saving. Workspace departure/reload guards include the open panel and active work. Page departure aborts outstanding network work, clears the key and invalidates callbacks; it does not save drafts automatically. Nothing saves an API-key field or authentication header. Private context snapshots are saved only by the explicit answer-save option below; nothing is persisted merely by selecting, reviewing or sending.

## Reusable device-local connections

The Q&A panel and prompt model dialog share explicit connection presets (name, HTTPS endpoint and model ID only). Select, edit, Save or Delete a preset; this clears the API-key field and invalidates the reviewed request without selecting sources or sending anything. Each request still requires reviewing the exact receiver and content before Send. Presets are unencrypted device-local metadata, excluded from backups and sync and preserved on the destination during restore. Never put secrets in preset metadata. See [connection preset behavior and limits](ai-model-workflow.md#device-local-connection-presets).

## Optional historical question/source snapshot

After an answer arrives, **Also save this exact question and reviewed source excerpts** is OFF by default. Selecting it shows the exact JSON that the answer-save action will retain: question, reviewed edited source IDs/labels/text, exact full reviewed prompt, canonical endpoint and exact model. It copies the immutable reviewed request without rereading originals. The preview warns that this may contain private information or secrets supplied in the text; inspect it before saving. API-key fields and authentication headers are never copied. Clearing or editing the request resets the choice.

The snapshot belongs to the first saved answer body version. Collection detail displays that version ID and the historical payload as plain text. It remains unchanged after answer revisions and after source edits, archival or deletion; it does not claim that a later edited answer was generated from that request. Source IDs and labels identify reviewed input. Answer citations remain unverified model claims. Imported metadata is user-provided, not cryptographic proof of model output. No automatic reuse, source resolution, fetching or model request is added.

### Review and copy the historical full prompt

In a saved collection item with a snapshot (including archived items), choose **Review historical full prompt**, inspect the literal read-only text and first answer version ID, then explicitly choose **Copy historical prompt**. This copies only `contextSnapshot.prompt` as shown, preserving line breaks, quotes and Unicode. It does not copy the answer or append the outer endpoint/model metadata; text inside the prompt may itself contain private information, URLs or secrets. The original **Copy excerpt** action remains separate. Closing the review cannot undo a clipboard write that has already started.

Review and copy do not resolve original sources, change stored data, request permissions or call a model. Source edits/deletion and later answer revisions do not change this historical input. Failed or unavailable clipboard writes leave the text selectable for manual copying without automatic retries. Double clicks share one pending write. Switching items, editing, archiving, refreshing, closing the review, disposal and pagehide/BFCache invalidate old feedback; reopening requires explicit review again. The interface supports English and Chinese; Spanish browsers retain the existing English fallback.

## Copy the displayed response

**Copy answer** and **Copy task JSON** write only the current response textarea to the clipboard on an explicit click. Edited task JSON is copied exactly, without parsing or reformatting. The action never appends the question, source snapshot, endpoint or key fields; the answer itself can repeat private input, so inspect it first. Empty or whitespace-only responses cannot be copied. The existing previous-request warning remains visible when copying an older answer after editing the request.

Copying does not save content, review tasks, change a reviewed task list, or mark an unsaved response as saved. Repeated clicks are ignored while a write is pending. A failed or unavailable clipboard API shows a manual-selection fallback without replacing request/save status. Feedback from an older response, cleared draft or closed panel cannot overwrite a later panel's state. No clipboard-read access or permission is added.

## Optional progressive Answer

The Answer-only toggle starts off and stays session-local. Both local review and endpoint review display the output and progressive setting. Changing output, toggle, question or selected sources invalidates review; switching output turns the toggle off and clears the key. Tasks always send `stream: false`.

Explicit Send is still required after exact request review and endpoint permission. The existing direct client supplies accumulated plain text through `onText`; the context controller keeps it in separate volatile partial state, never in the completed result or any store. The UI renders it using textContent in an explicitly incomplete section. Save and answer-copy controls cannot act on it. A previous complete response and its provenance remain separate, hidden while incomplete output is shown; a new review/edit clears the incomplete preview and restores the previous response with its ownership label.

Only the strict client's successful protocol completion (normal stop and `[DONE]`, within its existing timeout, wire/text limits and metadata validation), followed by current-session/workspace checks, promotes the final response. EOF, malformed events, refusal/tool metadata, abnormal finish, timeout and cancellation cannot promote partial content. Stop retains an incomplete preview; retry and departure fence late chunks and completions. Hiding the document stops the request and clears the key; closing or pagehide also discards volatile text. This is not persistent background execution, and a provider may still charge for already-started work.

Validation uses synthetic SSE and mocked transport/permissions/storage only. No real provider account, API call or paid service was used. Actual provider compatibility remains unverified; no new permissions, dependencies or persistence schema were added.
