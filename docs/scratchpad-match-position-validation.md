# 便笺查找匹配序号：验证范围

2026-10-17 的本地合成验证。仅为既有便笺查找成功反馈增加“第n处/共m处”和绕回时的相同数字，不新增输入、编辑或替换控件。

## 行为与实现边界

- 明确点“上一处”“下一处”或按查找 Enter 后，沿用原有 `indexOf` / `lastIndexOf` 定位。首次 Next 是 1/m，首次 Previous 是 m/m 且不提示绕回；越过首尾才提示，唯一匹配再次导航也会绕回。
- 在同一查询和实际 textarea 文本快照上，以原生 `indexOf` 逐匹配统计总数和所选起点的序号，起点每次前进一个 UTF-16 单位以保留重叠。只保留计数等常量辅助状态，不保留匹配数组、不建立索引，也不在查询输入时扫描。不宣称严格最坏线性时间或新的性能上限。
- 完整 Unicode 单行查询、区分大小写、首尾空白、字面标点、不做 Unicode 规范化、UTF-16 选区偏移和当前 DOM 草稿范围均不改变。32,000 字符是保存上限，不是查找截断点。
- 仅在聚焦、设置选区和原有同步失效复核均通过后，通过原有 `textContent`、`role=status`、polite/atomic 状态元素发布数字。查询/文本变更、空查询、无匹配、非法 Unicode、聚焦或选择失败均不保留旧数字。
- 页面隐藏事件清除反馈和按住 Enter 的持有状态，不抢焦点、不清空查询、不自动搜索；销毁解绑该监听。卡片关闭、隐藏、脱离、controller 关闭及 View 重新挂载沿用原生命周期路径。未扩大工作区协议；仍保留的本页只读草稿维持原查找语义。
- 查找不调用 `setDraft`、save、Retry 或 `View.render` 来定位，不改导入预览、冲突预览、保存状态或错误。Store、Controller、schema、manifest、权限、版本和发布 workflow 均未修改。

## 本地模型证据

实现前只运行既有查找测试中首个真实绑定入口，在成功选择后新增精确断言 `Match 1 of 2.`；基线实际返回 `Match selected.`，该单入口红例已复现。其余新增用例未在基线上运行，不宣称均取得红例。

测试实例化实际 Scratchpad View，绑定既有有限 DOM 模型和带副作用记录的控制器；未修改旧辅助模型。原有十四项查找测试保留选区、绕回、输入法、Enter 持有、正常编辑、失败和无副作用断言，只精确更新受影响的成功文案。新增八项覆盖：

- `aaaa/aa` 三处重叠、正反向首尾及唯一匹配绕回；原 `ababa/aba` 两处重叠仍覆盖。
- emoji、多代码点 Unicode、规范化有区别的文字、空白重叠、大小写和 HTML/正则字面量的正确序号与 UTF-16 偏移。
- 对实际运行作用域的 `indexOf` 计数，确认查询 input、空/非法查询不触发扫描；无匹配/非法/空查询清除先前数字且不改变选区。
- 实际 DOM 草稿在 32,000 之后的两个匹配均计数，且以 DOM 中的 LF 为准；原控制器 CRLF 文本、保存超限错误、导入/冲突预览不被改写。
- 编辑区 input 和 controller 文本更新后重新计数，controller 关闭后旧控件拒绝导航且清空。
- 在已有成功数字后，聚焦或选区设置期间的文本/查询变化、隐藏、关闭、抛错或未生效均不发布旧/新数字。
- 成功后页面隐藏、恢复、销毁及同 host 新 View 的独立反馈和监听清理；旧实例不接收新实例的隐藏事件。
- 英文、中文及英文 fallback 的三种成功模板无残留占位符，状态元素仍为纯文本 polite/atomic。

相关的原 Store、View 和 boundary 测试同时复查保存、冲突、导入、输入法及存储隔离；模型测试不等同于原生浏览器验证。
