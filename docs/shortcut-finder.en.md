# Find saved sites

Choose **Find saved sites** beside the shortcut heading and placement control. This separate local panel searches your saved shortcut titles, addresses and category names across all categories in the current workspace by default. It never sends the query to a web search provider.

- Choose **Filter by category** to browse that exact category without typing, or combine it with a text query. Category counts are saved-site totals before text filtering; result counts reflect both filters. Empty categories remain selectable. If category metadata is deleted, the exact ID remains selected: orphaned saved sites with that ID remain visible under the ID label. If no saved sites retain that ID, results stay empty instead of widening to all categories. Clear resets the query, category and matching mode; closing discards them. The native category picker keeps its normal keyboard behavior.
- With focus on the page outside editing fields, press **/** to open the same panel, even when the web search module is hidden. The shortcut uses the typed character: Shift is allowed when your keyboard needs it for /; Ctrl, Alt, AltGraph and Meta combinations are left alone. It does not run during IME composition, key repeat, or while another dialog or menu is open. Text inputs, selectors and range controls keep their own keys. Ordinary buttons and links support this shortcut. Browser and address-bar shortcuts are unchanged.
- To disable this single-character shortcut, go to **Settings → Shortcuts → Module Visibility**, clear **Use / to open Find saved sites**, and save. Open a new tab, or finish your work before refreshing an existing tab. The visible **Find saved sites** button still works when the shortcut is disabled, and no / key hint is shown. Re-enabling follows the same save-and-refresh steps. Older configurations default to enabled. This preference is included in settings backups and optional configuration sync; no query is saved.
- **Match → Continuous phrase** is the default: the entire query must appear together in one title, address or category, with internal spaces and punctuation kept literal.
- Choose **Match → All words** to split on spaces or other whitespace, including fullwidth spaces. Every word must appear somewhere in the same saved site’s title, address or category, in any order. For example, `GitHub 开发` or `github.com 开发` finds GitHub in a category named 开发. Words are literal substrings; punctuation, quotation marks, `OR` and `-` are not special operators. There is no fuzzy matching.
- Both modes ignore case and canonical Latin accents, and support Chinese and other Unicode text. Fullwidth characters are otherwise kept as typed. Empty input with All categories selected shows guidance; selecting a category alone browses it in either mode. Match mode is temporary, preserves the current query/category when switched, and returns results to page one. Clear or closing restores Continuous phrase. No filter change launches a site.
- Results show title, category and address. Duplicate records remain distinct. Pages contain up to 50 results.
- Use local Up/Down keys to reach results, then activate a button with Enter or Space. Escape closes the panel and returns focus to where it was before the panel opened. IME composition does not launch a site.
- Clear or close discards the temporary query. Searching does not change shortcuts, categories, Tasks, layout or manual coordinates.

An explicit result activation briefly reserves a blank tab while checking the latest saved record. Deleted or changed results are refused and refreshed; read failure leaves a retryable message. Canceling closes only the still-blank tab owned by that activation. A tab you navigate yourself is never overwritten or closed. New duplicate records with stable IDs resolve independently; ambiguous legacy duplicates without IDs are refused rather than guessed.

Opening a selected website is normal navigation and can use the network. Typing, result paging and dismissal use no external provider, history lookup, clipboard access or stored query. Applied settings refreshes defer reloading while this panel or its validation is active, just as they preserve unfinished task work.

## Explicit All workspaces scope

Choose **Workspaces → All workspaces** to search saved sites in every active workspace on this device, including Default. Results show their workspace name; category choices are labeled **Workspace · Category**. Identical titles, URLs, category IDs and copied shortcut IDs in different workspaces stay separate. Opening a result opens only that site in a new tab; it does not switch workspaces, mark a workspace used, change Tasks or alter an open editor. No icons or previews are fetched.

Current workspace is unchanged and remains the default every time the panel opens. Switching scope keeps the text and matching mode, resets the category filter and starts a fresh read. Clear resets text/category/matching mode while retaining the chosen scope. Closing discards the scope and filters. Changing the query, filters or scope, closing, hiding the page or receiving a relevant source change cancels pending verification and closes only its still-owned blank tab. There is one activation-only exception: the exact still-owned, visible blank reserved by your click may take the foreground and hide the source page while verification finishes. If that blank becomes hidden, is navigated/closed by you, or can no longer be verified as the same blank document, activation stops. Hidden source pages never perform new All scans or adopt their results. Leaving or closing the source page also retires pending checks, even when it was already hidden behind that blank. Results are rechecked before every opening, including copied IDs, the original workspace generation and migration lineage, saved URL, category labels and layout/settings fences. Ambiguous legacy duplicate URLs without stable IDs are refused within their own workspace.

All is deliberately all-or-unavailable: unreadable, missing, malformed, future-version, over-limit or conflicting data in any active workspace prevents partial results or misleading empty totals. A newly created empty workspace is valid: absent links/categories mean no saved records, without supplying default sites. Explicit malformed arrays remain unavailable. A saved address with an embedded username/password, including recognized disguised authorities, makes All unavailable rather than showing credentials; the stored address is not changed. Ordinary query parameters are not treated as credentials. Other unsupported addresses cannot be opened. Choose Current workspace or close and reopen to retry; there is no automatic recovery or repair.

### Local read and concurrency boundary

All does not initialize a session, migrate data, contact Sync/providers, switch a workspace or write storage. It requires the normal current session to have already opened successfully. It reads a fixed set of 30 control/legacy keys, then only the exact live bundle keys listed by the validated registry. It does not read Trash/orphan bundles, previous-generation bundles, or directly request global Sync/privacy, collections or prompt-library keys.

Chrome storage reads complete values at top-level keys. Reading a bundle therefore also brings its saved notes/tasks/recovery values into the local validation function; the pre-migration snapshot can contain original unknown fields and provider settings, and a restore journal can contain historical prompt/collection data. These incidental values are discarded after validation and are not searched, returned as result tokens, rendered, logged, exported, cached durably or sent over the network. Only projected site/category data, workspace identity/labels and in-memory ownership are retained while the panel is open.

Supported limits are 100 registry entries, 20,000 links, 10,000 displayed category choices (including orphan categories), and 8 MiB of projected JSON. The raw limit is 64 MiB per validation pass: the initial complete control-plus-live-bundle pass counts all its returned JSON values together; the final control pass, including the selected bundle during opening, has its own 64 MiB budget. The preliminary metadata read is separately bounded. Repeated reads are not added to one lifetime counter; 64 MiB is not a peak-memory promise. Exact-key byte preflights help reject large sources before fetching, but are not atomic and cannot prevent a larger allocation if storage changes before a read. Returned data is bounded again. Image-heavy bundles can exceed the supported total even when their site list is small; nothing is silently skipped or truncated.

Acquisition holds the workspace lifecycle lock, then the existing task, focus and local-write locks. Both the initial and final native reads compare legacy roots and control metadata together; activation's final read also includes the selected bundle. Navigation is synchronous while those locks are still held. This serializes cooperating current/legacy writers and detects changes present in the explicit snapshots, with storage events providing additional cancellation. It is not a browser transaction or a guarantee against arbitrary writers that ignore all locks and withhold notifications after the final returned snapshot.

## Native keyboard-preference verification

On 2026-10-10, Chrome for Testing 155.0.8059.39 on the cloud Linux desktop passed the enabled-default, disable/save/safe-refresh, click fallback and re-enable/save/safe-refresh flows. The disabled button showed no `/` hint. Settings search and the English/Chinese checkbox and guidance rendered correctly. All 60 tested runtime files matched commit `291fb22836f24deee3ea8822aabddd7e5e396d92` (same tree as the locally tested `2c7b2db`). The owned test browser was closed.

This test used explicit refresh on an empty dashboard, not a claim of immediate hot updates. Chinese coverage was rendering/search, not a second toggle cycle. Screen readers, alternate keyboard layouts, dark/narrow views and live providers were not tested in this pass. Deterministic suites separately passed 725 Node tests and 19 Python packaging tests.

## Search interaction reference

The optional all-words interaction takes inspiration from [linkding’s documented AND search](https://github.com/sissbruecker/linkding/blob/27b7303baf41bb28babc610ac8eaa486e1ddfab5/docs/src/content/docs/search.md), published under the [MIT license](https://github.com/sissbruecker/linkding/blob/27b7303baf41bb28babc610ac8eaa486e1ddfab5/LICENSE.txt). This is an independent local implementation; no linkding code, parser, dependency or service is included. Unlike its broader query language, this finder has only the two explicit literal matching modes described above.
