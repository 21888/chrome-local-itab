# 1.1.36 · 从精确版本新建结果草稿 / Result drafts for exact prompt versions

## 新增

- 在提示词当前预览的版本旁直接选择「为此版本保存结果」，新标签页打开空白收藏草稿，并显示明确的提示词正文版本关联。
- 保留旧版本变量会话时，关联跟随真正使用的旧版本，不自动改为最新版本。

## 修复

- 严格拒绝缺失、重复、混合或冲突的启动参数，避免记录跳转、网页选中文字捕获和提示词版本草稿相互覆盖。
- 明确保存时在现有工作空间锁内再次核验活动提示词和精确正文版本；过期、归档或不可用的来源显示可理解的错误。
- 备份界面恢复下载测试等待真实就绪状态，消除固定等待导致的竞态；没有改变备份运行逻辑。

## 注意事项

- 只传递本地提示词和版本 ID，不读取剪贴板、不预填结果正文、不自动保存、不联网，也不增加持久数据结构或权限。
- 来源页的变量和编辑状态保留；目标页必须由用户填写正文并明确保存。
- 大量读失败、过期事件、异步启动与保存时变更由独立模型检查覆盖；最终源码通过 1,694 项 Node 与 53 项 Python 回归；原生 Chrome 验证旧版本新标签草稿、空白未保存状态、明确保存精确关联、返回源页变量、键盘导航、归档后的保存保护与失效启动参数。

## English

### Added

- Open a new empty collection draft directly from the exact prompt version used by the current preview, with a visibly reviewed reference.
- Retained old-version previews keep their actual version rather than silently linking to the newest saved body.

### Fixes

- Reject missing, duplicate, mixed or conflicting startup routes so record navigation, selection capture and prompt-version drafts cannot overwrite each other.
- Revalidate the active exact prompt/version inside the existing workspace lock on explicit save; unavailable sources show actionable errors.
- Backup recovery-download tests await real readiness instead of a fixed delay; backup runtime behavior is unchanged.

### Notes

- Only local stable IDs are handed off. No clipboard read, filled result body, automatic save, network request, new persistent schema or permission.
- Source variables and editor state remain intact. The user supplies result content and explicitly saves in the new tab.
- Independent models cover read failures, stale events, startup races and save-time changes; final source passed 1,694 Node and 53 Python tests. Native Chrome verified retained-version handoff, blank unsaved draft, explicit exact-reference save, preserved source variables, keyboard navigation, archive save guards and unavailable startup routes.
