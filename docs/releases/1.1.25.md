# 1.1.25 · 精确提示词关联 / Exact prompt links

1.1.25 新增精确提示词关联，延续工作空间、提示词库及 AI 收藏。旧版记录与截图保留各自的版本来源。

## 新增

- AI 收藏的新草稿和「编辑详情」提供本地提示词与精确正文版本选择器，无需手填 ID。可以选择已有提示词的当前版、旧版，以及归档或恢复快照中可找到的精确版本，并查看字面纯文本预览。
- 只改变选择不会修改草稿中的原关联或写入已保存记录。核对预览后，明确选择「将链接应用到草稿」，再「保存到本地」才会保存关联。应用不会替换摘录或注释；放弃草稿会放弃未保存的关联变更。移除关联也先作用于草稿，需保存才生效。
- 保存的是提示词 ID 与不可变正文版本 ID 的精确配对。提示词改名或新增正文版本不会改绑，关联从不自动跟随最新版。归档与恢复快照来源分别标注；精确版本缺失时保留原引用，不按名称、正文或最新版猜测替代。
- 读取失败与版本缺失分别提示，可刷新本地提示词重试。完整备份恢复状态未确定时不读取或应用新关联；收藏保存结果不确定时，先检查 / 重试同一次保存。

## 修复

本版本没有单独的既有功能修复项；新增功能的保护与限制见下文。

## 注意事项

### 范围与备份

不增加网络请求、权限、模型调用、存储 schema 或备份格式。沿用完整本地备份 schema 4：收藏保留精确引用，需要迁移提示词正文时必须同时选择提示词模块；关联本身不把提示词全文复制进摘录。未保存草稿不进入备份，普通设置 JSON、Chrome Sync 和 Drive 的范围不变。既有容量、纯本地未加密数据、替换而非合并的恢复限制继续适用。

## English

1.1.25 adds exact prompt links while retaining workspaces, the prompt library and AI collections. Earlier release notes and screenshots retain their own version provenance.

### Changes and use

- New collection drafts and Edit details offer an existing-prompt picker and an exact body-version picker, with no manual ID entry. Current, older, archived and recovery-snapshot versions can be selected when available, with a literal plain-text preview.
- Selection alone changes neither the draft's existing reference nor the saved record. Review the preview, explicitly Apply the link to the draft, then Save to local. Applying never replaces the excerpt or notes. Discarding the draft discards unsaved link changes; unlinking also requires Save to take effect.
- A saved link pairs the prompt ID with an exact immutable body-version ID. Renaming a prompt or adding a body version never rebinds the link; it never follows latest. Archived and recovery-snapshot provenance is labeled. Missing versions retain their original reference, with no substitution by name, matching text or latest version.
- Read errors are distinct from missing versions, with local refresh available. An uncertain complete-backup restore blocks reading or applying new links. For an uncertain collection save, check/retry that same save first.

### Fixes

No separate fixes to existing features are included; safeguards and limitations of the new feature are documented below.

### Scope and backups

No new network requests, permissions, model calls, storage schema or backup format. Existing complete-backup schema 4 preserves exact collection references; select the prompt module too when migrating linked prompt bodies. Linking does not copy the prompt body into the excerpt. Unsaved drafts remain excluded. Ordinary settings JSON, Chrome Sync and Drive scope is unchanged. Existing capacity limits, unencrypted local storage and replacement-rather-than-merge restore rules still apply.

### Verification

The final combined full regression passed 1,458 Node and 52 Python tests, including the additional independent-audit checks.

Bounded native cloud Linux Chrome acceptance passed older-version selection, selection-only without writes, Apply/discard, Save/reopen, prompt rename and new v3 retaining the v1 link, archive provenance, and unlink/discard. Narrow-window checks covered 100% and 125% zoom; 566 pixels is the outer browser width, not a measured CSS viewport or physical phone. An actual 3,649-byte complete-backup download preserved the exact reference, all three prompt body versions and the unchanged excerpt.

Those native results do not establish recovery-snapshot selection, missing/read-failure injection, exhaustive locale/theme/keyboard coverage, browser-restart durability or network inspection. Keep supported behavior distinct from tested scope.
