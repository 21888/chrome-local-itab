# 1.1.136 · 工作区升级兼容与启动提示 / Workspace upgrade compatibility and startup diagnostics

## 新增

- 工作区无法打开时显示中英文安全提示与受限错误代码，保留草稿导出入口。

## 修复

- 兼容旧设置中的 onlineWallpapers 布尔隐私字段，避免合法旧资料在工作区迁移校验时被拒绝；合成旧资料测试覆盖原字段和隐私选择保留，并验证失败时拒绝不安全写入；这不构成对用户实际资料安全的保证。
- 区分工作区读取或启动失败与已删除、过期标签页，不再把一般启动失败显示为工作区已删除。未捕获有效工作区身份时禁用修改操作；已有会话的列表读取失败不额外接管自动保存暂停。

- 工作区迁移末段再次核对旧资料并观察变更；旧标签页在 registry / activation 写入期间改动原资料时，拒绝发放旧快照会话并提示冲突，保留原资料和迁移副本。该保护针对已测试并发窗口，不宣称跨标签页存储的绝对原子性。

## 注意事项

- 三项修复各自独立提交；升级数据保护门禁文档维护不计作功能。本次复现并修复一种旧资料兼容问题，尚未确认它就是用户截图中加载失败的真实原因；旧网址问题不在本次修复范围内。
- 最终功能源码串行全测 3601 Node / 84 Python 通过，320 个 JS 语法及 JSON / diff 检查通过。前一候选组合全测首轮一个测试文件进程失败，不计作通过；未推断该进程失败原因。
- 最终源码原生验收包含英文 registry 晚写、中文 activation 晚写及中文旧布尔 true 正常进入默认工作区；4 份回执（3 个原生观察页面及 5 个脚本场景）通过。晚写场景首次启动拒绝捕获会话身份，原资料新值、恢复副本旧值及已迁移 bundle 旧值均保留，拒绝后没有追加写入。
- 已知界面限制：旧资料冲突警告已明确显示且修改操作禁用，但禁用的工作区选择器和状态仍可能显示「正在加载」；这不是仍在迁移或可继续写入的信号。
- 第一项原生验收首次 iframe 加载在 25 秒超时；未修改代码，原样重跑通过。该超时不计作通过，也不推断原因。
- 使用精确生产文件和合成数据验证，未完成真实安装态升级验收。没有新增权限、依赖、外部请求或 CSP 修改；123 个运行文件白名单不变，运行包不含测试资料、用户备份或凭据。
- 本次为 GitHub 批次发布，不代表 Chrome Web Store 已提交或上架。升级前保留原扩展目录并备份已保存资料；不要清空存储或卸载重装来处理启动错误。
