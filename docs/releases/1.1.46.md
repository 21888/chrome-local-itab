# 1.1.46 · 待办快速输入的组合输入保护 / Tasks composition safeguards

## 新增

- 待办快速输入显式跟踪组合输入状态，与已有编辑流程保持一致。

## 修复

- 组合输入尚未结束时，快速添加、表单提交和离开页面前的草稿保存不会提前写入。
- 空的组合输入也保留草稿保护；较晚的输入、失焦与过期回调不会错误清除新的输入状态。
- 组合结束后的普通添加保持可用，较新草稿不会被先前保存的完成回调清空。

## 注意事项

- 本次修复来自真实控制器/存储配合 DOM 事件模型的健壮性检查，不代表已复现 Chrome 原生输入法缺陷。
- 原生输入法候选操作与辅助技术仍需独立验证。
- 最终完整本地测试通过 1,839 项，Python 检查通过 53 项。较早资源争用时的超时不计作通过；完整 CI 仍是发布前置条件。
- 原生浏览器普通添加、失焦保留草稿、键盘添加和重载冒烟通过；不等于原生输入法验收。

## English

- Tracks quick-entry composition explicitly and prevents premature Add, submit or departure draft saves while composition is active.
- Protects empty active composition, final input, stale blur callbacks and newer drafts during overlapping saves; ordinary post-composition addition remains available.
- This is model-demonstrated robustness work, not a reproduced native Chrome IME defect. Native IME/assistive-technology validation remains separate.
- The final complete local suite passed 1,839 tests plus 53 Python checks. Earlier contended timeouts are not counted as passes; complete CI remains required.
- Bounded native ordinary Add, draft blur, keyboard Add and reload smoke passed; native IME validation remains unperformed.
