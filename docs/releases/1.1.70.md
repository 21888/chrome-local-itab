# 1.1.70 · 保留模型对话框键盘焦点 / Retain model-dialog keyboard focus

## 新增

- 模型运行、优化与比较状态更新时，为被禁用的当前控件提供对话框内有效焦点目标。

## 修复

- 避免运行/保存等操作禁用当前焦点按钮后落到页面正文，导致 Escape 无法按对话框规则工作。
- 只在当前焦点确实失效时恢复，不覆盖仍有效的用户焦点或其他对话框所有权。

## 注意事项

- 不改变模型请求、权限、保存或停止规则；忙碌状态下允许的关闭行为保持既有安全边界。

- 集成聚焦测试通过 159 项，Python 通过 53 项；未重跑本地聚合，发布仍须确切提交的原有完整 CI 通过。
- 原生浏览器使用 20 个生产匹配资产和声明的内存响应/权限，验证键盘 Run 发送后 Stop 及成功完成均保持对话框内焦点；比较与优化发送后，实际 Tab 移到有效 Close，完成不抢焦点。Escape 经过必要的普通丢弃确认返回各触发按钮，未保存响应或采纳建议。
- 正式比较键盘轮次前一次鼠标误触发送已单独披露并重载，不计为键盘证据。仅英文浅色桌面范围；只读焦点指示不是 AX/读屏审计，也不验证真实提供商、授权、持久化或中文/深色/窄屏。

## English

- Keeps keyboard focus within run, refinement and comparison dialogs when state changes disable the currently focused control.
- Prevents lost body focus from breaking Escape handling while preserving valid user focus and other dialog ownership.
- Request, permission, save and Stop behavior remain unchanged, including existing safe-close restrictions while busy.

- Integrated focused tests passed159 cases and Python checks passed53. No local aggregate was repeated; publication requires the exact commit’s existing complete CI gate.
- Native browser interaction with20 byte-identical assets and declared memory responses/permissions verified keyboard Run Send→Stop and successful completion retain in-dialog focus. Comparison and refinement preserved valid Close focus reached by real Tab while pending. Escape returned to each launcher through normal discard confirmation where needed; no response was saved or proposal accepted.
- A preliminary mouse-triggered comparison was disclosed and reset before the formal keyboard round; it is not counted as keyboard-Send evidence. Coverage is English/light desktop. Read-only focus instrumentation is not an AX/screen-reader audit; live providers, grants, durability and Chinese/dark/narrow remain unverified.
