# 1.1.75 · AI 上下文问答停止等待 / Stop pending AI context requests

## 新增

- 无新增产品功能。

## 修复

- AI 上下文问答在权限检查、工作区检查或请求回调未返回时，停止操作仍可解除当前请求的等待并恢复编辑。
- 隔离已停止请求的迟到回调，避免其发送旧请求、覆盖新结果或解除新请求的忙碌状态；停止提示保持到下一次明确操作。
- 保留正在进行的本地保存事务保护；停止网络请求不会取消已经进入保存阶段的写入。

## 注意事项

- 确定性合成测试覆盖五个挂起阶段、旧回调隔离、界面取消及本地写入保护；未调用真实 AI 服务商，未在原生浏览器复现挂起请求的停止。
- 已完成英文 Clarity 暗色桌面的安全原生界面检查：空来源的本地请求预览、编辑后预览失效、清空草稿、Escape 关闭并返回焦点、重新打开及重载后临时草稿清空。没有输入密钥，也没有点击 Allow 或 Send；这不是原生 Stop 验收。停止无法撤销服务商已执行的工作或费用，不自动重试。
- 不改变权限申请范围、模型请求格式、现有解析限制或保存内容。

## English

- No new product feature. AI context Q&A can stop waiting and restore editing even when permission, workspace or transport callbacks remain unresolved.
- Late callbacks cannot send an old request, replace a newer result or unlock its controller. The stopped status remains until the next explicit action.
- In-progress local saves retain transaction protection; stopping a request does not cancel an already-started save.
- Deterministic synthetic tests cover five stalled stages, late-callback isolation, UI cancellation and write protection. No real provider was called and no native stalled-request Stop scenario was reproduced. A bounded English Clarity dark desktop UI smoke passed for empty-source local review, edit invalidation, draft clearing, Escape focus return, reopen and empty temporary drafts after reload. No key was entered and neither Allow nor Send was activated; this is not native Stop acceptance.
- Stop cannot undo provider work or charges and does not retry. Permission scope, request format, parser limits and saved content are unchanged.
