# Local iTab 1.1.149

## 新增
- 在设置的隐私分区增加 Codex 官方用量帮助和 Grok 官方控制台入口，并纳入设置搜索。
- 明确 Local iTab 尚未接入 Codex 或 Grok 实时订阅用量，不读取或显示用量与余额；API 账单不等于订阅用量。

## 修复
- “Skip to settings” 跳转到始终可见的设置搜索框，避免切换设置分区后跳到隐藏的外观分区。

## 注意事项
- 官方链接仅由用户点击或键盘激活后打开。Codex 链接打开帮助文档，Grok 链接打开官方控制台；登录、限额和重置时间由官方站点处理。
- 链接不会授予账号访问权限，也不会在 Local iTab 内刷新用量。独立的 Claude 实验仍默认关闭，并保留其单独的权限审阅流程。
- 官方入口原生检查使用合成内存数据，并在默认跳转前拦截链接激活；未访问真实账号或验证真实用量。
- Skip 链接在默认外观、搜索后隐私分区和 Claude 深链隐私分区三个场景中，经真实 Tab/Shift+Tab 与 Enter 验证焦点到达搜索框，并保留所选分区和搜索内容；使用合成数据，未宣称安装扩展验收。

## English
- Added official Codex usage-help and Grok dashboard links to Privacy settings and settings search. Local iTab is not connected to their real-time subscription usage and does not read or display usage or balances. API billing is not subscription usage.
- The “Skip to settings” link now targets the always-visible settings search input, avoiding a hidden Appearance panel after section changes.
- Links open only on user activation. Codex opens a help guide; Grok opens its official dashboard. Sign-in, limits and reset times remain the official sites' responsibility. These links do not grant account access or refresh usage inside Local iTab. The separate Claude experiment remains off by default with its own permission review.
- Official-link native checks used synthetic in-memory data and intercepted link activation before navigation. No real accounts or actual usage were verified. Native Tab/Shift+Tab and Enter checks covered default Appearance, searched Privacy and a Claude deep-link opening Privacy. All focused the search input while retaining the selected section and query. These checks used synthetic data, not an installed-extension acceptance run.
