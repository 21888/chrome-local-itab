# 1.1.146 · 只读导入状态与明确保留当前设置 / Read-only import status and explicit keep-current decisions

## 新增

- 恢复页将当前工作区的导入操作状态与保留的配置副本分开显示。当前目标和原恢复副本分别比较摘要，明确区分匹配、不匹配、缺失、不可用、无记录、无效记录和不支持版本；历史副本不会被当作当前操作。原始导入文件未提供时，不声称核验其身份。
- 设置→数据新增只读审阅「保留当前已保存设置并结束这次未核验导入」的明确决定。仅适用于有效pending记录、当前目标已变化、完整原恢复仍匹配原摘要且保全槽空闲的情况。取消、离开该区或隐藏页面会撤销审阅；未保存草稿不被保存、丢弃或纳入决定。
- 增加全安装范围共用的一份不可覆盖本地保全记录，保留决定时已保存配置、完整原恢复、原pending记录及来源身份。独立恢复页可在该工作区不再属于当前登记时继续只读发现历史证据。

## 修复

- 明确确认后仅写入保全根记录，不改写或把旧pending记录标为verified，不自动开始导入、恢复或Sync。审阅与提交有独立的存活和锁内精确校验；写入结果不确定时仅提供只读重新检查，不自动重试、回滚或删除证据。
- 随后选择Manual或Drive文件仍是另一项明确决定：必须为选定文件与最新已保存状态重新确认，确认仅一次有效，新的正常导入保留最新恢复副本。普通重试标志、伪造确认对象或已过期审阅不能代替该确认。
- Complete恢复与复制工作区在既有锁内核对精确的原操作及保全证据；不相关或变化后的pending记录不会继承旧决定。重置保留保全槽且不释放容量，后续历史快照轮换不会移除独立根记录。

## 注意事项

- 只读摘要匹配本身不会完成、解除或结清pending导入，也不授予下载资格。该明确决定只处理满足条件的特定操作，并非任意pending冲突的自动解锁。原恢复不匹配、记录不安全或保全槽已有内容时继续安全阻断。
- 所有工作区共用一个最多8 MiB、另有深度及节点预算的本地槽位，无删除、退休、驱逐、覆盖或第二槽。另一冲突不能继续占用新槽。重置与下载均不释放容量。
- 保全内容是本地历史证据，不是加密保险箱或可移植备份；普通Settings、Drive、Sync和Complete导出不包含它。原恢复已有的提供方记账只留在本地，不在摘要中展示。卸载、清除扩展数据、删除浏览器资料、任意存储改写或降级不在保全保证范围内。
- 决定时配置仅供调查导出。原恢复必须独立通过现有严格配置文件审阅规则，保全摘要不能绕过凭据、缺失字段或不支持内容检查。下载不等于恢复。本批没有取得真实事故资料，不承诺找回早前已丢失的数据。
- 本批含三个独立功能提交：只读状态、保全槽核心、明确决定及后续准入。冻结组合通过4504 Node / 84 Python、1052聚焦检查、231独立安全探针与2容量探针，静态和构建检查通过。运行白名单由130增至132项，新增两个本地模块，无新增扩展权限。
- 原生Chrome验收使用完整生产Options与合成RAM：Appearance→Data是设置分区导航，并非多个浏览器标签页的原子性验收。Review/Cancel无额外写入，明确确认只写一次根记录，原pending及恢复不变。此前quote输入触发一次既有自动保存，不计作决定写入，也不冒称未保存草稿；另一轮真实未提交topic输入在取消新导入后保持且零写入。
- 原生同文件和不同文件均经过独立再次确认：拒绝不写入，接受后产生新的已核验导入，旧保全槽不变。仅保全根记录、无登记或工作区的独立Recovery测试仍可发现历史证据，原恢复单独审阅但未下载。首次只读状态native覆盖匹配、不匹配、无效及不可用；不可用案例是bundle身份无效，并非真实存储读取故障。
- 四份决定验收记录与132份最终运行资源一致。独立夹具是离线检查点副本，不是共享实时多标签页；无真实Drive/Sync账户、提供方、权限、安装扩展或磁盘崩溃持久性结论。只读与审阅不证明实际丢失数据已找回。
- 仅发布GitHub，不上传截图或验收资料，不变更Chrome Web Store上传或提交。

## English

- Separate current workspace import status from retained configuration copies in Recovery. Compare target and original-recovery fingerprints independently, distinguishing match, mismatch, missing, unavailable, absent, invalid and unsupported receipts. Historical copies never become current operations. Without the original import file, its identity is not verified.
- Add a read-only Settings → Data review for an explicit decision to keep currently saved settings and end this unverified import. Eligibility requires a valid pending receipt, a changed target, an intact original recovery matching its recorded digest, and an empty preservation slot. Canceling, leaving the section or hiding the page invalidates review. Unsaved drafts are neither saved, discarded nor included.
- Add one installation-wide immutable local evidence record retaining saved-at-decision configuration, complete original recovery, the pending receipt and source identity. Independent Recovery discovery remains available when the owning workspace is no longer in the current registry.
- Explicit confirmation writes only the root evidence record. It never relabels the original pending receipt as verified or automatically starts an import, recovery or Sync. Private live review ownership and exact locked checks guard submission. Uncertain readback offers read-only recheck without automatic retry, rollback or evidence deletion.
- A later Manual or Drive import is a separate decision requiring new explicit confirmation for the selected request and latest saved state. Confirmation is single-use; normal import captures the latest recovery copy. Generic retry flags, caller-created objects and stale review handles cannot provide consent.
- Complete restore and duplication recheck the exact receipt and preservation evidence under existing locks. Different or changed pending receipts do not inherit an older decision. Reset retains the slot and its occupied capacity, and subsequent prior-snapshot rotation cannot remove independent root evidence.
- Read-only matches never settle or unlock an import or grant download eligibility. The explicit decision applies only to its eligible operation, not arbitrary pending conflicts. Mismatched original recovery, unsafe records and occupied capacity fail closed.
- All workspaces share one local slot bounded to 8 MiB plus depth/node limits. There is no deletion, retirement, eviction, overwrite or second slot. Another conflict cannot consume a new slot. Reset and download do not free capacity.
- This is local historical evidence, not an encrypted vault or portable backup. Ordinary Settings, Drive, Sync and Complete exports exclude it. Existing provider bookkeeping stays local and is omitted from summaries. Uninstall, extension-data clearing, profile deletion, arbitrary storage edits and downgrade are outside the preservation guarantee.
- Saved-at-decision configuration is investigation-only. Original recovery must independently pass existing strict file-review checks; the archive digest cannot override credential, missing-field or unsupported-content gates. Download is not restoration. No real incident profile was acquired and no recovery of previously lost data is promised.
- Three independent feature commits form this batch: read-only status, preservation core, and explicit decision/admission. Frozen combined source passed 4504 Node / 84 Python tests, 1052 focused checks, 231 independent safety probes and 2 capacity probes, plus static/build checks. The runtime allowlist grows from 130 to 132 files with two local modules and no added extension permissions.
- Native Chrome acceptance used the complete production Options page with synthetic RAM. Appearance→Data was Settings-section navigation, not a cross-browser-tab atomicity test. Review/Cancel added no writes; explicit confirmation made one root write and retained the pending receipt and recovery unchanged. Earlier quote typing triggered one existing autosave write, neither a closure write nor an unsaved-draft demonstration. A separate genuinely unsubmitted topic draft survived canceled new import with zero writes.
- Native same-file and different-file imports both required separate new confirmation: refusal did not write, acceptance produced a new verified import, and the old archive stayed unchanged. Independent Recovery with only the archive root and no registry/workspace still discovered history and separately reviewed original recovery without downloading it. Initial read-only-status native checks covered match, mismatch, invalid and unavailable; the unavailable case was invalid bundle identity, not a real storage I/O failure.
- Four decision-acceptance receipts correspond to 132 byte-identical final runtime assets. Separate fixtures were offline checkpoint copies, not shared live multi-tab state. No real Drive/Sync accounts, providers, permissions, installed-extension behavior or disk/crash durability are established. Inspection and review are not evidence of recovered lost data.
- GitHub only; no screenshots or QA artifacts uploaded and no Chrome Web Store upload or submission changes.
