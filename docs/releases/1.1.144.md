# 1.1.144 · 工作区恢复上下文与历史副本检查 / Recovery workspace context and historical copies

## 新增

- 从设置页进入恢复页时保留工作区上下文，先显示归属可核对的匹配副本，提示被隐藏的其他或未确定归属副本；可明确切换查看全部，再返回请求的工作区视图。无参数直接进入时显示全部。
- 只读检查增加一份已知的工作区替换前快照，展示其保留的历史工作区，即使当前登记已不再列出该ID。历史记录标明代际、快照时间、当时回收站状态，以及与当前登记的关系；当前与历史匹配分开计数。

## 修复

- 空、重复、无效或不明确的工作区参数显示警告，不静默回落到默认工作区；找不到匹配副本不代表已删除。切换视图、刷新和页面恢复会使过期审阅与下载控件失效。
- 历史归属须通过严格结构及ID/代际一一对应检查；大小、层级、数量与两次读取一致性限制保持有效，当前来源优先。无效历史快照不被赋予归属或展示为有效副本。

## 注意事项

- 两项功能只检查已保留内容，不扫描任意存储键或孤立记录，不追踪恢复事务引用，不写入、切换或自动恢复工作区，也不自动选择、审阅或下载副本。
- 历史归属不等于当前工作区仍存在，也不等于内容完整性已核验。外层历史快照没有持久化历史校验值，只能生成可能省略不支持字段或私人字段的调查导出；该调查文件不是可导入备份。只有带自身有效校验的内嵌副本通过原有严格格式、凭据与无损检查后，才可另行审阅配置文件。
- 不保证找回真实用户早前丢失的内容。此次没有增加历史保留数量、修复或自动解除导入冲突功能；1.1.143的未核验导入保护与限制保持不变。已经产生新工作区导入记录的资料不应直接降级到不认识该记录的旧版。
- 两个功能独立提交后合并为此补丁版。冻结组合源码通过4200 Node / 84 Python及331项聚焦测试与静态检查；运行白名单保持130项，无新增扩展权限或运行文件。
- 原生浏览器验收覆盖工作区上下文、明确查看全部、审阅、刷新与重复参数警告；历史副本验收显示已移除的命名工作区为0份当前/2份历史，Default为2份当前/2份历史，全部视图12份。没有历史校验的裸配置不能审阅为恢复配置；内嵌有效校验副本可明确审阅，刷新使旧审阅失效。
- 原生页面使用生产文件配合合成RAM与明确的测试操作，未安装实际扩展、未执行配置导出或恢复导入。离线种子构建有预期的合成写入；浏览器只读检查计数为零写入、网络和提供方调用，页面无错误。未验证真实资料恢复、磁盘持久性、崩溃、全部语言或全部无障碍行为。
- 仅发布GitHub，不上传截图或验收资料，不变更Chrome Web Store上传或提交。

## English

- Preserve the workspace context when entering Recovery from Settings. Initially show matching copies with validated attribution and disclose hidden other or unattributed copies. Explicitly switch to all copies and back to the requested view. Direct entry without a query shows all copies.
- Inspect one known retained pre-replacement workspace snapshot, including historical workspace IDs absent from the current registry. Rows label recorded generation, snapshot time, historical Trash state and their relationship to the current registry. Current and historical matches are counted separately.
- Empty, duplicate, invalid or ambiguous workspace parameters show a warning rather than silently selecting Default. No matching copy is not proof of deletion. View changes, refresh and page resumption retire stale review and download controls.
- Historical attribution requires strict supported structures and one-to-one ID/generation associations. Existing size, depth, entry and two-pass consistency checks remain, with current sources prioritized. Invalid history is not attributed or presented as a valid copy.
- Both features inspect retained content only. They do not enumerate arbitrary storage or orphan keys, follow recovery-journal references, write, switch or automatically restore workspaces, or automatically select, review or download a copy.
- Historical attribution proves neither current membership nor content integrity. The outer snapshot has no stored historical checksum; its projected investigation export may omit unsupported or private fields and is not an importable backup. Independently checksummed nested copies must pass the existing strict format, credential and lossless-value gates before a separate configuration-file review is available.
- This does not guarantee recovery of a real user's previously lost data, increase retained history, repair records or automatically resolve import conflicts. The protection and limits introduced in 1.1.143 remain. Profiles containing its new workspace import receipt should not be directly downgraded to older versions that cannot recognize it.
- Two independent feature commits precede this patch release. Frozen combined source passed 4200 Node / 84 Python tests, 331 focused checks and static checks. The runtime allowlist remains 130 files, with no new extension permissions or runtime files.
- Native-browser checks covered workspace context, explicit all-copies navigation, review, refresh and duplicate-query warnings. Historical checks showed 0 current/2 historical copies for the removed named workspace, 2 current/2 historical for Default, and 12 in the all-copies view. A bare configuration without a historical checksum could not be reviewed as a recovery configuration; an independently checksummed nested copy allowed explicit review, and refresh retired the old review.
- Native pages used production files with synthetic RAM and explicit test instrumentation, not an installed extension; no configuration export or recovery import was performed. Offline seed construction intentionally wrote synthetic setup data. Read-only browser counters recorded zero writes, network and provider calls, with no page errors. This does not verify real-data recovery, persistence, crashes, all languages or exhaustive accessibility.
- GitHub only; no screenshots or QA artifacts uploaded and no Chrome Web Store upload or submission changes.
