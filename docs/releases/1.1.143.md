# 1.1.143 · 导入重试保护与冲突指引 / Import retry protection and conflict guidance

## 新增

- 配置导入新增按工作区保存的设备本地摘要记录，与替换内容和导入前恢复副本一起提交。只有读回核对当前设置及恢复副本后，才标记为已核验。
- 设置页区分未核验导入、内容已变化和需要明确开始新导入的情况，并提供恢复页入口，供检查、导出保留副本。

## 修复

- 导入已提交但确认或读回失败时，再次选择同一文件只核验、结清原操作，不再次覆盖导入前恢复副本；重开设置页或换标签页仍保留这层保护。
- 前次导入仍未核验时，不直接导入另一份文件。若前次核验成功，先停止并要求重新审阅、确认新文件；若当前设置或恢复副本已经变化，则安全阻断写入。
- 已核验导入之后修改设置，再导入同一文件需额外明确确认新操作；确认后允许导入，并将当前编辑保留为最新恢复副本。

## 注意事项

- 未核验导入之后发生内容变化的冲突，本版本不会自动解除。重开设置、反复重试或导出副本均不会解锁；恢复页仅供检查与导出，请保留导出副本供后续受控处理。
- 摘要记录只保存在设备本地的对应工作区，不进入配置导出、Drive 或 Chrome Sync；完整备份与便携恢复文件格式不变。旧版（包括 1.1.142）不能识别新工作区记录时会拒绝读取，请勿将已产生此记录的资料直接降级。
- 正常的新导入仍会轮换最新恢复副本，并非永久历史备份。空间不足或核验失败不会通过删除恢复副本来腾出空间，也不保证恢复此保护上线之前已丢失的数据。
- 两项功能分别提交后合并发布，另有测试与文档适配提交。冻结组合源码通过 4144 Node / 84 Python 测试及静态检查（345 JavaScript、111 JSON、10 Python 文件）；未新增扩展权限或运行文件，运行白名单保持 130 项。
- 原生浏览器通过设置页真实文件选择器与确认框验收，覆盖英文默认工作区的未核验导入、同文件核验及重载后零写入重放；已核验后编辑的取消零写入与明确新导入保留编辑副本；中文命名工作区的未核验后编辑、同文件及重载后不同文件持续阻断；以及英文不同文件先结清原导入、再次明确选择确认后才执行新导入。五份新验收记录均通过。
- 原生页面使用生产运行文件配合合成 RAM 存储和故障注入，不是实际安装扩展或真实用户资料；页面计数未发现网络、提供方、权限、剪贴板或远端写入副作用。本地合成存储写入均对应测试场景。
- 自动化使用合成存储与页面模型，不证明真实用户历史事故已恢复、已安装扩展行为、浏览器崩溃或磁盘原子性。
- 仅发布 GitHub，不上传截图或验收资料，不变更 Chrome Web Store 上传或提交。

## English

- Add a workspace-scoped, device-local receipt containing hashes, submitted with the replacement and its pre-import recovery copy. An import is verified only after matching readback of both current settings and retained recovery content.
- Settings distinguishes unresolved imports, changed content and operations that need explicit new-import confirmation, with a Recovery link for inspecting and exporting retained copies.
- If storage committed before acknowledgment or readback failed, retrying the same file verifies and settles the earlier operation without overwriting its pre-import recovery copy again. Protection persists across reopening Settings and other tabs.
- A pending import blocks a different file. Successful verification first settles the previous operation and requires reviewing and confirming the new file again. Changed settings or recovery content block the write safely.
- After a verified import and later settings edits, importing the same file again requires an additional explicit new-operation confirmation. Accepting it permits the new import and retains current edits as the latest recovery copy.
- A pending import whose retained settings or recovery content changed has no automatic resolution in this version. Reopening, retrying or exporting does not unlock it. Recovery only inspects and exports copies; keep the exports for a later controlled resolution.
- Receipts remain local to their workspace and are excluded from configuration exports, Drive and Chrome Sync. Complete-backup and portable recovery-file formats are unchanged. Older versions, including 1.1.142, reject affected workspaces whose new receipt key they cannot recognize; do not directly downgrade such a profile.
- Ordinary new imports still rotate the latest recovery copy; this is not permanent backup history. Quota or verification errors never delete recovery content to make room. This cannot guarantee recovery of data lost before the protection existed.
- Two feature commits precede this batch release, with a separate test/documentation adaptation commit. Frozen combined source passed 4144 Node / 84 Python tests and static checks of 345 JavaScript, 111 JSON and 10 Python files. No new extension permissions or runtime files; the runtime allowlist remains 130 files.
- Native-browser acceptance used the Settings file picker and confirmation dialogs: English Default pending import, same-file settlement and zero-write replay after reload; canceling after edits to a verified import without writes, then explicitly accepting a new import with those edits retained as recovery; Chinese named-workspace fail-closed retries after edits to a pending import, including a different file after reload; and an English different-file retry that settles the prior import before requiring another explicit selection and confirmation. All five new acceptance records passed.
- Native pages used production runtime files with synthetic RAM storage and fault injection, not an installed extension or real user data. Page counters recorded no network, provider, permission, clipboard or remote-write side effects; synthetic local storage submissions were intentional test cases.
- Automated checks use synthetic storage and page models. They do not establish recovery of a real user's historical incident, installed-extension behavior, browser-crash safety or disk atomicity.
- GitHub only; no screenshots or QA artifacts uploaded, and no Chrome Web Store upload or submission changes.
