# 1.1.142 · 导入写入边界与连接重载 / Import write boundary and connection reload

## 新增

- AI 上下文问答和已保存提示词模型对话框新增「重新加载已保存连接」，显式重新读取设备本地连接列表，保留当前字段、密钥、问题、编辑后的来源片段、请求审核和已有回答。
- 只有名称、网址和模型全部未变的连接才保留选中状态；发生变化或已删除的记录转为手动/未保存选择，当前草稿保持原样。应用某个连接仍需明确选择。

## 修复

- 配置导入将所选工作区、其恢复副本以及提供的全局设置合并为一次 chrome.storage.local.set 提交，再逐项读取验证，消除先替换工作区、后单独提交全局设置失败形成的分步写入问题。
- 连接重载失败保留旧列表，初次读取失败可重试；等待期间阻止重复重载、发送、权限请求和保存。关闭仍可用，页面隐藏、关闭或字段变化会使过期读取结果失效；传输中或写入结果未定时不允许重载。

## 注意事项

- 一次存储提交不等于跨存储事务或普遍的「报错就绝未写入」保证：浏览器可能已完成提交，随后确认或读取验证失败。错误会明确呈现，已提交工作区仍携带导入前的恢复内容；不会盲目回滚或重试。不能据此保证找回早前丢失的数据。
- 连接重载只读取本地列表，不调用提供方、不请求权限、不写入存储，也不自动应用新端点或重新创建已删除记录。未来明确保存仍是另一个操作。
- 两项功能独立提交后合并发布。冻结组合源码通过 4125 Node / 84 Python 与静态检查；未新增扩展权限、存储结构或运行文件，运行白名单保持 130 项。
- AI 原生验收在合成内存 host 中挂载生产组件，覆盖英文上下文与中文模型对话框的重载、失败重试和中文等待状态；302 项验证通过。未覆盖完整 newtab/prompts 宿主页、真实提供方或所有语言/入口组合。
- 恢复页英文 raw/Default 与中文 portable/命名工作区均完成原生审核及单独下载，两份实际 7236 字节配置文件与生产 Blob 完全一致。后续导入是脚本调用生产 prepareRestoredConfig → setAll，并非原生 Options 文件选择器；每份 116 项断言验证提交前拒绝不变、单次合并成功、提交后读回失败仍保留恢复副本，以及网址/重复项/隐藏坐标、个人模块和其他工作区保持。
- 验收仅使用合成内存，不证明真实用户资料恢复、安装扩展、浏览器崩溃或磁盘原子性。页面级记录零远端写入、网络、提供方、权限与剪贴板调用；AI重载无存储写入，导入成功与读回失败用例有明确预期的本地内存提交。
- 仅发布 GitHub，不上传截图或验收资料。Chrome 商店已上传的 1.1.137 仍等待资料校验提示处理，不替换上传包或提交本版本。

## English

- Add explicit Reload saved connections in both context Q&A and the saved-prompt model dialog. Refresh the device-local list while retaining fields, key, question, edited source excerpts, exact request review and existing response.
- Keep a selected connection only if its name, URL and model still match. Changed or deleted records detach into manual/unsaved selection without replacing the draft. Applying another connection remains an explicit selection.
- Submit the selected workspace, its recovery copy and supplied global settings in one chrome.storage.local.set call, then verify every submitted key. This removes the separate second global-settings submission that could fail after replacing the workspace.
- Preserve the previous connection list on reload failure and allow retry after initial read failure. Pending reads block duplicate reload, transport, permission requests and saves; Close remains available. Hide, close and field changes invalidate stale reads. Transport and pending/uncertain writes block reload.
- A single submission is not a cross-storage transaction or a universal no-write-on-error guarantee. Browser storage may commit before acknowledgment/readback fails. Errors remain visible and the submitted workspace retains its pre-import recovery content; there is no blind rollback or retry. This does not guarantee recovery of earlier lost data.
- Reload reads local presets only, without provider calls, permission requests or storage writes. It never automatically applies a new endpoint or resurrects a deleted record. An explicit future Save is a separate action.
- Two independent feature commits precede this batch release. Frozen combined source passed 4125 Node / 84 Python tests and static checks. No new extension permissions, storage schema or runtime files; the runtime allowlist remains 130 files.
- AI native checks mounted production components in synthetic RAM hosts, covering English context and Chinese model reload, failure/retry and a held Chinese read; 302 assertions passed. Full newtab/prompts host pages, real providers and every language/view combination were not covered.
- Recovery native review and separate download covered English raw/Default and Chinese portable/named destinations. Both actual 7236-byte files exactly match production Blobs. Subsequent import was scripted production prepareRestoredConfig → setAll, not native Options file-picker acceptance. Each receipt passed 116 assertions for unchanged pre-submission rejection, single combined success, recovery retained after committed readback failure, exact URLs/duplicates/hidden coordinates, personal modules and other workspaces.
- Synthetic RAM evidence does not establish real-user recovery, installed-extension behavior, browser-crash or disk-atomicity guarantees. Page counters recorded zero remote writes, network, provider, permission and clipboard calls. AI reload writes no storage; successful import and committed readback-failure cases intentionally submit local RAM changes.
- GitHub only; no screenshots or QA artifacts uploaded. The existing Chrome Web Store 1.1.137 upload remains blocked on metadata validation and is neither replaced nor resubmitted.
