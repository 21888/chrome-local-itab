# 1.1.71 · 非流式响应完整性边界 / Require complete non-streaming answers

## 新增

- 非流式模型回答也必须明确正常停止，才能作为完整结果进入保存流程。

## 修复

- 缺失或非正常 finish_reason，以及混有非空工具、函数或拒绝结果的文本，不再被误当成完整回答。
- 不完整结果不能通过问答保存进入收藏或导出；仍兼容可选元数据的 null/空值，不扩大保存格式。

## 注意事项

- 非标准第三方代理若省略正常 stop 标记，其响应会被拒绝；需符合受支持的 Chat Completions 响应格式。
- 不新增权限或自动请求，不改变流式已有完整性边界；真实服务商兼容性需独立验证。

- 集成聚焦检查通过 190 项，Python 通过 53 项；本地未重跑聚合，发布须本次确切提交通过原有完整 CI。
- 原生浏览器以 20 个生产匹配资产和声明的内存传输/权限验证三场景：缺失结束原因、stop 加非空拒绝均拒绝且不可保存/零收藏写入；stop 加 null 可选字段正常展示，单独明确保存产生一次写入。实际内存收藏视图确认一个条目、一个版本和确切正文。
- 仅英文浅色桌面单模型界面；问答视图、其他工具/函数形状为自动化范围，不宣称真实提供商、耐久扩展存储、中文/深色/窄屏或读屏验证。夹具导航链接被有意禁用，嵌入收藏检查不算生产导航验收。

## English

- Non-streaming answers must explicitly finish with normal stop before becoming complete saveable results.
- Missing/non-stop finish reasons and text mixed with nonempty tool, function or refusal results are rejected. Incomplete Q&A results cannot enter saved collections or exports.
- Null/empty optional metadata remains compatible; no storage schema expands. Nonstandard proxies that omit stop are no longer accepted and must supply the supported Chat Completions completion boundary.
- No new permissions or automatic requests are added. Streaming retains its existing boundary; live-provider compatibility requires separate verification.

- Integrated focused checks passed190 cases and Python checks passed53. No local aggregate was repeated; publication requires the exact commit’s existing complete CI gate.
- Native browser interaction with20 byte-identical assets and declared memory transport/permissions verified three scenarios. Missing finish reason and stop plus nonempty refusal both rejected with Save disabled and zero collection writes. Stop plus null optional metadata displayed the exact answer; separate explicit Save wrote once. The actual embedded memory-backed collection view showed one item, one version and the exact body.
- Coverage is English/light desktop single-model UI. Context view and other tool/function shapes remain automated evidence; live providers, durable extension storage, Chinese/dark/narrow and screen-reader behavior are unverified. The fixture intentionally blocks its navigation link, so embedded collection inspection does not establish production navigation.
