# 1.1.67 · 商店材料核对指引 / Correct store preparation guidance

## 新增

- 选包指引要求核验同一发布的源提交、完整 CI、运行包、校验值与验收限制，不再把旧开发版本或历史素材当作当前候选。

## 修复

- Privacy Practices 指引不再把开发者无收集后台等同于表单无需披露；要求按实际本地处理、可选传输与当前官方定义逐项审查。
- 补充 BYOK、问答、可选历史输入快照及未加密备份的审阅范围，明确合成测试不代表真实提供商验收。
- 打包清单使用同一显式输出路径生成和校验，明确商店图标链接及选定版本核对。

## 注意事项

- 这是技术文档修正，除版本号外不改运行代码、权限或数据格式；未访问或更改商店后台、上传材料、提交审核或确认审批状态。
- 历史截图和包保留原出处；需要逐项验证其是否适合选定版本，不自动将其升级为当前材料。

- 三份技术文档与最终独立审查版本逐字节一致，Python 检查通过 53 项，运行包验证通过 108 个文件。与 1.1.66 包逐项比较，只有 manifest.version 改变，其余运行文件及清单字段完全相同。
- 文档版本未重复本地 JavaScript 聚合或浏览器验收；完整 CI 仍须对本次确切提交通过，不把既有原生测试扩称为新的商店审核或表单核验。

## English

- Store preparation now selects a release by verified source, complete CI, runtime package, checksum and documented acceptance limits rather than stale development versions or historical assets.
- Privacy guidance separates the absence of a developer collection backend from actual data-type and use disclosures, including local processing, optional provider requests, historical input snapshots and unencrypted backups.
- Packaging examples generate and verify the same explicit output path; the icon link is explicit and requires checking the selected release.
- Documentation only apart from the version bump: no runtime code, permissions or formats changed. No Store Dashboard access, upload, submission or approval-status change occurred. Historical assets retain provenance and require review before reuse.

- All three guidance files match the independently reviewed feature exactly. All 53 Python checks passed and the 108-file package was verified. Comparison with 1.1.66 found only manifest.version changed; all other runtime bytes and manifest fields are identical.
- No local JavaScript aggregate or browser gate was repeated for this documentation release. The exact commit still requires the existing complete CI gate; prior native evidence does not establish Store review or form verification.
