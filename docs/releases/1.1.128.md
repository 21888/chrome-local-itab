# 1.1.128 · 收藏摘录对照与键盘连续操作 / Saved excerpt comparison and keyboard continuity

## 新增

- 未归档 AI 收藏可显式“手动对照任意收藏摘录”，包括无提示词关联的上下文答案和手动摘录。候选来自全部当前未归档收藏，不受侧栏筛选限制，不自动选择；各自标注条目、正文版本、提示词关联及未经核验的来源网址。
- 原有同一精确提示词/版本的结果对比仍独立保留。历史输入仅标明关联首版回答，不把隐藏快照、旧正文或恢复数据当作当前摘录来源。对照只读，不请求模型、不联网、不写入、不复制或导出。
- 数据刷新/失败/变更清空对照，成功验证当前数据后才能重开。切换条目清除错误提示不会把旧缓存变成已验证数据；提供明确的“刷新已保存数据”恢复入口。

## 修复

- Finder 激活结果等待本地复核时，先把当前结果焦点移到查询框再禁用结果，避免 Chrome 将焦点丢到 BODY，保证 Escape 取消及 Tab 圈定继续生效；异步结束不抢回较新的焦点。
- 修复收藏对照预格式正文中裸 CR 视觉连行，仅显示副本将 CRLF/CR 转为 LF，并明确说明。原始正文、精确相等判断、既有复制和导出保持不变；看似相同的正文仍可能原始换行不同。

## 注意事项

- 本批为 Finder 修复、收藏对照功能和换行显示修复三个独立产品提交，另含一个测试专用提交。123 个运行文件，无新增权限、依赖或存储结构。最终整合严格全测通过 3270 Node / 84 Python，独立整合审查 35/35 和受影响回归 665/665 通过。
- 首次功能全测曾暴露原有测试的固定 event-loop 轮数等待竞态，不能据单独重跑通过视为修复。已在127基线受控延迟复现，并单独改为等待真实保存 Promise，同时增加延迟写入断言；未修改生产保存行为。
- 云端 Chrome for Testing 155 原生合成组件验收复现127 Finder负控 BODY 失焦/Escape失效，修后中英 pending、取消、Tab、晚到读取及较新焦点路径通过。模拟lease结果不代表真实Chrome标签页激活或空白页所有权验收。
- 收藏对照原生合成验收覆盖手动候选/原精确关联范围、来源边界、CR显示及视觉同而原文不同、键盘/200%布局、失败读取恢复和变更失效。最终18生产组件与候选相同；普通对照操作副作用计数为零，单独订阅测试的3次写入恰为明确合成元数据/正文/归档变更，未增加对照写入。
- 实际安装127未替换。测试使用内存适配器；真实provider/API、真实存储/标签页激活、系统剪贴板/导出、屏幕阅读器、原生IME和全部平台/生命周期组合未验。复制/导出原文边界仅由自动化覆盖。截图未上传，未提交 Chrome 商店。
