# 1.1.31 · 当前版本发布说明校验 / Validate current release notes

## 新增

- 本版本没有新增运行时功能。

## 修复

- 自动化测试现在读取 manifest 中的当前版本，并调用实际发布器的发布说明校验函数，检查对应的源码发布说明。缺失文件、缺少必需章节或不符合发布说明长度限制时，测试会直接失败，避免历史版本测试通过但当前说明在打包阶段才被拒绝。
- 保留发布器原有校验条件，不使用单独的宽松规则，也不改变发布、打包或上传逻辑。

## 注意事项

- 这是测试与发布说明维护更新；相较 1.1.30，除 manifest 版本号外，扩展运行文件保持不变。搜索、提示词、收藏、备份、权限、网络请求和存储格式均无功能变更。
- 新测试仅验证当前版本发布说明是否符合现有发布器要求，不验证文案事实、原生浏览器表现、上传结果或商店审核状态；发布仍需针对准确提交构建、检查产物并验证实际发布结果。
- 原始 1.1.23–1.1.29 说明的独立负向对照均被新测试以缺少必需章节拒绝；此项只证明能捕获该类缺陷，不表示修改了既有发布附件。
- 本次完整自动化回归通过 1,643 项 Node 与 53 项 Python 测试；没有跳过或取消的测试。
- 本次为测试维护，不新增原生浏览器验收，也不以历史截图替代新验收。

## English

### Added

- No new runtime features in this version.

### Fixes

- Automated tests now read the current manifest version and invoke the actual publisher's release-note validation helper against its source-controlled note. Missing files, required sections or acceptable note length now fail the test suite instead of allowing historical-note tests to pass before the current note is rejected during packaging.
- The publisher's existing validation rules remain intact. No alternative relaxed validator or changes to publishing, packaging or upload logic are introduced.

### Notes

- This is test and release-documentation maintenance. Compared with 1.1.30, extension runtime files are unchanged except for the manifest version. Search, prompts, collections, backups, permissions, network behavior and storage formats have no functional changes.
- The new test checks the current note against existing publisher requirements. It does not establish factual accuracy, native browser behavior, upload success or store approval. Publication still requires an exact-commit build, artifact inspection and verification of the actual release.
- Separate negative controls using the original 1.1.23–1.1.29 notes all failed with the required-sections error. This demonstrates detection of that defect class; it does not modify existing release assets.
- Full automated regression passed 1,643 Node and 53 Python tests, with none skipped or cancelled.
- This test-maintenance update adds no native browser acceptance coverage and does not substitute historical screenshots for new acceptance.
