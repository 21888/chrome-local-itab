# 1.1.68 · 拒绝完整备份中的重复键 / Reject duplicate backup JSON keys

## 新增

- 完整备份在 JSON 解析与模块重序列化前进行有深度/节点预算的语法扫描，保留并验证原始键的唯一性。

## 修复

- 嵌套全局提示词或集合中的重复键不再被 JSON.parse 静默覆盖，即使该模块未被选中也拒绝畸形档案。
- 共享扫描器按解码后的键识别转义等价名称，保留不同对象使用同名键的合法行为，并严格处理字符串、数字与结构语法。

## 注意事项

- 不变更备份 schema、导出内容或恢复确认流程；合法旧格式仍受既有验证和容量限制。
- 拒绝发生在读取/锁定/写入应用数据之前，不自动修复或选择重复值。

- 对重复字段提供明确英中提示：尚未开始还原，请选择有效备份；保留不确定写入错误的优先级，不以通用失败暗示需检查已保存资料。
- 变更相关聚焦检查通过 222 项，独立解析审查通过 291 项及 57,296 例语法差分；这些覆盖重叠，不相加。文案增量另通过 26 项聚焦检查，Python 通过 53 项。
- 本地聚合在 240 秒上限退出 124：592 通过、0 失败、132 取消，不是完整通过；20,000 链接用例未运行。发布须对应提交的未修改完整 CI 通过，不放宽断言。
- 实际安装扩展的最终英文浅色原生检查确认重复字段档案在替换审查前被明确拒绝。合法原七模块档案进入审查并 Escape 取消，证据来自此前解析器相同、仅错误文案不同的运行版本；本次门槛未还原任何文件。最终 108 个运行文件匹配包。
- 中文错误文本有自动化验证，未原生测试。原生界面没有零读写内部计数，零读写/锁保证属于解析器测试，不扩称原生遥测。
