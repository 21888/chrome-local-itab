# 1.1.24 · AI 结果收藏 / AI result collections

1.1.24 新增 AI 结果收藏，保留工作空间与提示词库基础功能，分别见 [1.1.22](1.1.22.md) 和 [1.1.23](1.1.23.md)。原生验收使用最终修正后的 82 文件冻结运行包（manifest 1.1.21）；1.1.24 相对该包仅修改版本号。

## 新增

- 新标签页增加「AI 收藏」入口，在独立标签页手动保存原文摘录、独立注释、类型、工具 / 模型备注、标签和可选来源网址。收藏跨工作空间共用，代码和 HTML 保持纯文本。搜索覆盖标题、当前正文和标签，不覆盖注释、来源或历史正文。
- 元数据修改不增加正文版本。修订正文需先审阅当前 / 拟修订文本再确认；恢复历史正文会追加新版本，保留后续历史。归档与从归档恢复保留记录和版本。过时标签页不能覆盖最新保存，草稿保留供核对、另存新记录或明确放弃。
- 独立 JSON 导出包含收藏、归档、正文历史、注释、精确关联和恢复快照；可以仅从导出副本移除来源网址，本地记录不变。修正下载被重复 JSON 编码的问题，实际下载现可一次解析为对象。
- 完整本地备份扩展至 schema 4，全局收藏只保存一次。恢复需要明确选择全局收藏目标并审阅替换范围；这是替换而非合并。恢复前保存并验证副本，替换后读回验证；被替换的收藏另保留恢复快照。未选择的模块及旧备份中不存在的收藏模块保持不变。
## 修复

- 修正下载被重复 JSON 编码的问题，实际下载现可一次解析为对象。
- 修正收藏页默认主题属性，以及不区分大小写的本地化键冲突造成的错误标题；修正备份预览误用待办计数名称，改为收藏与归档摘录计数。

## 注意事项

### 范围、隐私与限制

- 仅保存用户手动提供的摘录，不是完整对话备份。没有自动读取 AI 网站、采集对话、模型调用、新网络请求或新权限；点击来源仍会访问对应网站。工具 / 模型标签不是来源认证。
- 精确提示词 ID 和正文版本 ID 必须成对填写，目前仍显示为未解析关联，不读取关联正文、不自动跟随最新版本，也不按名称改绑。后续选择器不属于此版本。
- 最多 200 条收藏（含归档），每条正文最多 32,000 字符、20 个正文版本；收藏库预算 2 MiB（内部另预留 16 KiB），最多 8 份内部恢复快照。达到限制会拒绝操作，不截断正文或自动淘汰历史。没有永久删除、历史清理或恢复快照清理入口，导出不会释放容量。完整备份文件上限 32 MiB。
- 草稿与拟修订文本只在当前标签页，刷新或离开可能丢失，不进入备份。独立收藏 JSON 不是完整备份格式，当前没有独立收藏导入入口；迁移应使用设置 → 数据 → 完整本地备份。普通设置 JSON、Chrome Sync 和 Drive 不包含收藏。
- 本地数据和导出未加密。移除来源网址不清除正文、注释和历史中的链接或个人信息，不等于匿名化。完整恢复前副本只保留最新一份；不确定的写入可能已部分生效，恢复保护不保证浏览器崩溃时的原子性，也不保证自动回滚。

## 验证与证据

集成后的完整自动化回归通过 1,442 项 Node 与 52 项 Python 测试。云端 Linux 原生 Chrome 的有界验收通过：手动保存并重载字面原文、注释独立编辑、标签 / 类型查询、审阅修订与历史恢复、归档往返、跨标签页过时草稿保护、真实 JSON 下载及来源仅在副本中移除、schema 4 全局替换与恢复前副本。下载文件比对确认原收藏和历史恢复、被替换数据可恢复、过时草稿未进入导出；最终收藏计数文案刷新另经原生预览核对，未重复执行替换。

浅色桌面和深色窄窗口已有原始截图；窄窗口为 553 像素外窗口，不是实体手机或测量后的 CSS 视口。未完成真实输入法 / 全 Unicode 与空白矩阵、原生限额与故障注入、中断恢复、旧备份、未选模块保留、全部主题 / 语言 / 键盘矩阵或浏览器重启耐久性验收；网络行为未做原生抓包。自动化测试与有界验收不能替代这些未测项目。

## English

1.1.24 adds AI result collections while retaining the workspace and prompt-library foundations. Native acceptance used the final corrected, frozen 82-file runtime with manifest 1.1.21; 1.1.24 differs from that runtime only in its version number.

### Changes and fixes

- Adds a separate AI collection tab for manually supplied literal excerpts, separate notes, types, tool/model labels, tags and optional source URLs. One local collection is shared across workspaces. Code and HTML remain text. Search covers titles, current bodies and tags, excluding notes, source URLs and historical bodies.
- Metadata edits do not add body versions. Body revisions require current/proposed review and confirmation; restoring historical text appends a new version without erasing later history. Archive and restore preserve records and versions. Stale-tab saves are rejected with drafts retained for review, saving as new or explicit discard.
- Standalone JSON export includes saved and archived records, history, notes, exact references and recovery snapshots. Optional source omission affects the exported copy only. Fixes double JSON encoding: actual downloaded files now parse once as objects.
- Complete backup schema 4 contains the global collection once. Restore requires an explicit global destination and replacement review; it replaces rather than merges. A verified pre-restore copy and collection recovery snapshots preserve displaced data, followed by read-back verification. Deselected modules and collections absent from legacy archives remain unchanged.
- Fixes missing default-theme attributes and the heading affected by a case-insensitive locale-key collision. Backup review now uses collection-specific saved/archived excerpt counts instead of task labels.

### Scope and limits

No automatic conversation capture, AI-site reading, model calls, new network requests or new permissions. This is not a complete conversation backup; clicking a source still visits that website. Tool/model labels are user notes, not verified provenance. Exact prompt and body-version IDs must be paired and remain unresolved: no linked body display, latest-version following or name-based reassignment. A future picker is outside this version.

Limits include 200 records including archives, 32,000 characters per body, 20 body versions, a 2 MiB collection budget with an additional internal 16 KiB reserve, and eight internal recovery snapshots. Limits reject rather than truncate or evict. No permanent deletion, history cleanup or snapshot cleanup UI is provided; export does not free capacity. Complete archives have a 32 MiB file limit.

Drafts and proposed revisions are tab-local and excluded from backups; refresh or departure may lose them. Standalone collection JSON has no import UI and is not a complete-backup archive: use Settings → Data → Complete local backup for migration. Ordinary settings exports, Chrome Sync and Drive do not include collections. Local data and exports are unencrypted; omitting source URLs does not anonymize bodies, notes or history. Only the latest complete pre-restore copy is retained. Uncertain writes may already have partially changed data; recovery safeguards do not promise crash-atomic storage or automatic rollback.

### Verification

The integrated candidate passed 1,442 Node and 52 Python tests. Bounded native cloud Linux Chrome acceptance covered literal creation/reload, metadata-only editing, tag/type lookup, reviewed revisions and history restoration, archive/restore, stale-tab protection, actual JSON downloads, copy-only source omission, schema 4 global replacement and verified recovery copies. Download comparisons confirm restored record/history, exact displaced-data recovery and exclusion of unsaved stale drafts. The final collection-count wording was separately checked in native review without another replacement.

Original light-desktop and dark-narrow screenshots are included. The narrow browser had a 553-pixel outer width, not a measured CSS viewport or physical phone. Real IME/full Unicode/whitespace matrices, native quota/fault injection, interrupted restore, legacy archives, deselected-module preservation, exhaustive theme/locale/keyboard coverage, browser-restart durability and native network inspection remain untested.
