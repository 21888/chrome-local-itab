# 1.1.26 · 统一 AI 资料库搜索 / Unified AI library search

1.1.26 新增统一 AI 资料库搜索，延续工作空间、提示词库、AI 收藏及精确提示词关联功能。既有版本记录和截图保留各自来源。

## 新增

- 在新标签页导航中选择「搜索 AI 资料库」，同时查找已保存的提示词与 AI 摘录；可筛选全部、提示词或 AI 摘录。标题、当前正文和标签按完整输入文字进行不区分大小写的字面匹配，不执行正则表达式或 HTML。
- 结果显示类型、匹配字段和 Unicode 安全的原文片段，按标题、类型、稳定 ID 确定顺序。方向键移动结果焦点，Enter 通过原生链接在新标签页打开对应记录；Escape 关闭并返回入口按钮。
- 链接定位精确的稳定记录 ID，不按名称或排序猜测目标；当前标签页未保存草稿保持不变。目标无效、已删除或已归档时明确提示，不自动显示第一条、最新或其他记录。
- 资料库变化时立即清除旧结果，再重新读取两侧资料库。读取不可用与没有匹配内容分别显示，避免把读取失败当作空库。

## 修复

本版本没有单独的既有功能修复项；新增功能的保护与限制见下文。

## 注意事项

### 范围与限制

只搜索当前已保存内容，不搜索历史正文版本、恢复副本、已归档内容、未保存草稿或填写后的变量值。搜索是本地字面匹配，不是语义搜索或模型执行，也不会自动采集网页。

不新增权限、网络请求、模型调用、存储 schema 或备份格式，不写入新的搜索索引。现有资料库容量、纯本地未加密存储及备份范围不变；搜索结果不能替代完整本地备份。

## English

1.1.26 adds unified AI library search while retaining workspaces, the prompt library, AI collections and exact prompt links. Existing release notes and screenshots keep their original provenance.

### Changes and use

- Choose Search AI library in the new-tab navigation to search saved prompts and AI excerpts together, with All, Prompts and AI excerpts filters. Match a literal, case-insensitive phrase in titles, current bodies and tags; input is never interpreted as a regular expression or HTML.
- Results show their type, matched field and a Unicode-safe literal snippet, with deterministic ordering by title, type and stable ID. Arrow keys move through results; native Enter opens the corresponding record in a new tab. Escape closes the dialog and returns focus to its entry button.
- Links target the exact stable record ID without guessing by name or list order, preserving unsaved drafts in existing tabs. Invalid, missing or archived targets show explicit states instead of silently opening the first, latest or another record.
- A library change clears stale results immediately before both libraries are reread. Unavailable data is distinguished from no matches rather than treating a read failure as an empty library.

### Fixes

No separate fixes to existing features are included; safeguards and limitations of the new feature are documented below.

### Scope and limits

Only current saved content is searched. Historical body versions, recovery copies, archived records, unsaved drafts and filled-in variable values are excluded. This is local literal matching, with no semantic search, model execution or automatic webpage capture.

No new permissions, network requests, model calls, storage schema or backup format are introduced, and no new search index is written. Existing library capacity, unencrypted local storage and backup scope remain unchanged. Search results are not a substitute for a complete local backup.

### Verification

The integrated candidate's full automated regression passed 1,476 Node and 52 Python tests. Relevant checks cover literal matching, Unicode snippets, type filters, deterministic order, asynchronous cross-library changes, read failures, destination validation, retained drafts and keyboard interactions.

Bounded native Chrome acceptance passed combined search across both record types and type filters, literal snippets, keyboard opening of exact prompt and collection records in new tabs, preservation of the source-tab draft, Escape focus return, and explicit invalid/missing/archived-target notices without fallback. Light and dark narrow-window checks passed; 556 × 848 pixels describes the outer browser window, not a measured CSS viewport or physical phone. All 85 frozen runtime file hashes remained unchanged.

Real IME composition and forced read-failure injection were not exercised natively. This bounded acceptance does not establish an exhaustive browser, locale or keyboard matrix. See [unified-search native validation and untested scope](../ai-search-native-validation.md) and [itemized acceptance evidence](../qa/unified-ai-search-native/acceptance-notes.md). Historical screenshots are not native acceptance evidence for this feature.
