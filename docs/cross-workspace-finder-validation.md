# Explicit All-workspaces Finder: focused validation

Candidate baseline: local `3807ac1fb0e9ce25672335f04a56982e6fa477c4`, equivalent published `defab51a921468b3191832ef0c3d75335cd4e063`. Manifest remains 1.1.149; no schema or permission change. This is implementation/focused-test evidence, not a release or native-browser certification.

## Implemented boundary

- Current remains the default and existing adapter. New reader creation, native reads, byte preflights, locks and raw-storage subscriptions start only after explicit All selection. Close returns to Current.
- The reader calls the exact existing `Manager.prototype.checkLegacySource({readOnly:true})` method on a frozen no-listener facade, backed by the 27-key legacy projection from each fixed 30-key control snapshot. It never creates a Manager or calls the live manager/session readiness, migration, selection, writer or provider APIs. The old production comparison is unchanged.
- Initial metadata discovery is three exact keys. The initial full fence is 30 controls; only registry-listed active bundles follow. The final scan fence is 30 controls; activation's final fence is those 30 controls plus the selected exact bundle. No get-all, root fallback, Trash/orphan/historical bundle enumeration or directly requested global prompt/collection/Sync/privacy data.
- Strict raw descriptors/prototypes/arrays/depth/byte/node checks precede permissive legacy validators. Known registry, activation, snapshot, conflict, bundle and restore headers are exact. Resolved conflicts and verified/recovered journals have positive tests; future or malformed equivalents fail closed. Bundle envelopes require schemaVersion 1 exactly. The values-level settings/layout schemaVersion supports 1/2 or an absent legacy value; future/null/type-invalid values are refused. Production-created empty values are legal, explicit null arrays are not.
- Raw control/snapshot/journal/bundle evidence stays within acquisition. Tokens keep only immutable site/category projections, identity and fences. Credential-bearing URLs make All unavailable before rendering; all original stored data is untouched. See the user guide for honest full-value reads, exact budget definitions and non-atomic concurrency limits.
- Workspace, personal-task, focus and local-write locks are exclusive and acquired in that order. Every activation repeats admission and compares migration lineage, session owner, target generation, displayed fields, category labels, layout/settings presence fences and strict stored URL. The host's All branch performs known synchronous validated navigation directly on its owned blank, without calling the tile component or assimilating a thenable. Current opening remains unchanged. A separate activation-only visibility guard admits the exact still-owned visible blank when its foreground opening hides the source; raw scans and snapshot adoption always require source visibility. Temporary blank visibility/pagehide/beforeunload listeners retire that lease on hiding/navigation/close and are removed before verified navigation. Document identity/access is rechecked at each awaited fence; a user-navigated document is never closed. A lazy All-only source pagehide listener also cancels navigation/closure/BFCache departure when the source is already hidden. It stops the reader and rejects refresh admission before native I/O, so departure starts no replacement reads.

## Focused automated checks

`tests/shortcut-finder-workspaces.test.js` covers production-generated migration/create metadata and a genuine empty workspace; exact keys; no writes/live-manager work; duplicate IDs across spaces; excluded Trash/orphans; raw sentinel privacy; strict hidden/accessor/symbol/pollution/sparse/cycle/depth/header failures; the four independently reproduced permissive baseline acceptance gaps; valid resolved/terminal cases; missing/unreadable/future/oversized data; schema and fence presence; legacy sequence ambiguity; strict URLs and credential rejection; session retirement; and cancellation.

Its fault-injection matrix changes legacy roots without events, activation lineage, Trash/generation state or a prepared restore at every native lock/read/byte-preflight await in activation. Final combined target/control reads also have a DOM regression with a silent target URL edit. Test providers/writers are absent or throwing. A 10 MiB synthetic image-heavy bundle remains searchable, while oversized returned data is refused even after a cheap preflight. A complete maximum-boundary fixture combines 100 workspaces, 20,000 links and 10,000 categories and verifies the last page/opening. A separate multi-bundle case proves the 64 MiB raw budget is cumulative across keys.

`tests/shortcut-finder-workspaces-view.test.js` loads actual Finder reader/controller/host/view modules with the existing DOM/event model. It covers zero added Current work; explicit scope and reopen reset; names/composite categories; source component/Tasks unchanged; blank reservation before awaits; opening; unreadable whole-scope status; query/category/match/Clear interruption; scope/Close/hidden/IME interruption; immediate owned-blank closure; duplicate clicks; user-navigated blank ownership; late old callbacks; stale query tokens; and English/Chinese labels. The actual newtab HTML script order is replayed in a browser-like JavaScript realm with a valid terminal journal, so missing captured validators cannot be hidden by CommonJS imports.

These are deterministic controller/DOM models. They do not certify native keyboard synthesis, real IME, browser focus painting, screen readers, responsive layout, extension APIs or live-provider behavior. Native Chrome, the aggregate full suite and publication are deliberately left to the coordinating integration pass.

## Production-renderer flow and category snapshot correction (2026-10-20)

A bounded dot-cloud Chrome check used the production new-tab renderer with a page-memory Chrome-storage fixture, not an installed extension. Synthetic Default, named Research and empty workspaces were generated through the unchanged production Manager migration/create and captured Session write paths with real validators. Default and Research each held two sites, including the same title/URL in different categories. No real data, external navigation, clipboard or file actions were used.

The English keyboard flow verified Current's two sites, explicit All's four separately attributed rows, the exact named category's two rows, and Close/reopen resetting to Current and an empty query. A scheduled named Session edit emitted the normal change event: the loaded All result refreshed to the new title without selecting that workspace. A synthetic one-shot named-bundle read rejection removed all results and reported All unavailable; Current remained usable and an explicit return to All recovered the complete four-site snapshot. The workspace selection stayed Default. Searching performed no writes; only the explicit synthetic Session edit added one write.

This flow exposed a view defect: unavailable All results still displayed the previous Current scope's enabled category choices and counts. The view now replaces those choices with a disabled, count-free placeholder during snapshot preparation/error. It retains only the filter identity for same-scope refresh and rebuilds enabled choices from the newly admitted snapshot. Focus moves to the query only when the selector being disabled owns focus; late completion does not reclaim newer focus. Reader admission, storage, locks, navigation guards, manifest and permissions are unchanged.

Deterministic regressions first failed on the old view, then passed for English/Chinese pending/error, Current fallback, successful All retry, retained same-scope category identity and focus ownership. All 142 related Finder tests passed. Native production-renderer recheck confirmed the unavailable placeholder was disabled/count-free, Current restored its two-site counts and results, and All retry restored the four-site counts and rows. In a fresh disposable fixture, a selected named category survived the scheduled Session edit with two matching rows, including the updated title. The native selector owned focus before refresh; focus moved to the query, not outside the dialog, and Close restored the Finder launcher. The final counters showed one explicit Session write, zero blocked external/file actions and Default still selected.

These observations do not certify installed-extension persistence, upgrade/restart/crash recovery, native IME, screen readers, result activation/blank-tab behavior or clipboard access. Those boundaries remain separate from this local synthetic search/refresh acceptance and do not resolve the historical data-loss incident.
