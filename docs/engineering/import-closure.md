# Local import closure: immutable one-slot evidence

The first core checkpoint contains the strict pure codec, independent read-only slot validation, and protected-key guards. It exposes no installer and changes no import admission. The slot is `__localItabImportClosureV1`, outside workspace scoped/global inventories, portable configuration and workspace migration sources.

The exact schema stores the original pending receipt, current presence-preserving configuration inventory (root privacy included, live Sync excluded), complete original recovery, lineage/workspace/generation provenance, action and review/decision timestamps. SHA-256 matches StorageManager's sorted-key JSON fingerprints. Recovery digest must equal the pending receipt's original recovery digest; current target must differ. Unknown fields, hidden properties, symbols, accessors, invalid prototypes, unsupported values, sparse arrays and unsafe keys fail closed. The 8 MiB, depth 64 and 200000-node limits apply conservatively to the whole envelope. No truncation is performed.

## Mutation boundaries

- StorageManager's ordinary key writers reject the root key. Legacy root reset enumerates removals while excluding even corrupt/future slot bytes. Workspace reset cannot see the slot through its scoped facade.
- Manager.verifiedSet rejects the key, including direct recovery and topology writes. Session read/write/remove inventories do not admit it. legacySource omits it from migration and branch comparisons.
- Complete Backup and workspace-preset generic write backends reject it. Other direct local-storage writers have fixed owned names. Combined restore's prior/next authorities remain restricted to registry, prompts and collections; the new key is not an authority.
- Manual, Drive, Sync and Complete serializers use their existing explicit configuration/module allowlists. No receipt or archive becomes portable.

## Lock audit for the forthcoming explicit service

Workspace configuration/privacy writers acquire lifecycle shared, then workspace-origin write exclusive. Lifecycle/topology writers acquire lifecycle exclusive. Legacy configuration writes use `local-itab-local-write`; presets use tasks then focus. The closure service must acquire lifecycle exclusive, then the existing legacy compatibility chain tasks → focus → local config. It must perform direct strict storage reads before any existing permissive copying and never call ready/initialize or reentrant public writers inside these locks. Combined restore and unresolved legacy state block closure. Source reads and pre-submit checks remain inside the lock; UI confirmation remains outside it.

This contract excludes uninstall, browser Clear extension data, profile deletion, arbitrary DevTools writes, and incompatible older binaries. There is no downgrade guarantee, archive retirement, second slot, automatic cleanup or provider/network work.

## Explicit decision and later imports

Options uses StorageManager.reviewImportClosure / commitImportClosure / cancelImportClosure / recheckImportClosure. Review returns only a frozen summary. A module-private WeakMap binds the exact detached source to that review, its UI liveness callback, and its review epoch. Cancel, another review, recheck, or a consumed ticket disables commit. Review does not initialize migration. Commit reacquires lifecycle exclusive → tasks → focus → legacy config, checks source and absence, hashes the preserved candidate, and performs one final combined raw read of source identities plus slot before its sole root-key set. False/throw acknowledgments trigger read-only verification; there is no retry, deletion, receipt settlement, or rollback. A preserved exact slot with changed live state returns RECORDED_LIVE_CHANGED. Unestablished readback returns UNCERTAIN and consumes the review.

A valid record closes only its exact full pending receipt under the same migrationId/workspace ID. Generation remains historical provenance. The live receipt is not rewritten verified. Two equivalent reviews return the first archive without another write; a changed current snapshot returns ALREADY_CLOSED_HISTORY_ONLY and is never said to have been newly archived. Recheck is read-only and independently finds the root record; one final consistent read prevents mixed identity/slot attribution. Active relation is specific to the pinned Options workspace; other owners are historical and stale/invalid pinned generations are unknown.

Manual/Drive first encounter throws RESTORE_CLOSED_RECONFIRM with a private review handle for both same and different files. Only a new explicit confirmClosedRestore call issues a five-minute, UI-owned WeakMap capability bound to request hash, current exact source/provider state, full receipt, generation, and exact slot. The import consumes it once. Its freshness guard runs through Session.set → writeBundle → verifiedSet **after** asynchronous writer preparation, immediately before the actual replacement set. Generic booleans and caller-crafted objects cannot admit a closed import. The normal new receipt/recovery protocol then runs independently and the root archive remains untouched.

Complete Backup's existing explicit review stores exact closure evidence privately with its source snapshot. Review, lock admission, recovery preparation, and every staging/authority submission recheck it. Duplicate checks under the lifecycle lock and copies current data/recovery while removing the copied receipt; source and root archive remain unchanged. Generic root facades reject archive set/remove/clear. Reset retains slot capacity. Complete topology replacement may remove the owner; repeated prior-snapshot rotation cannot remove the independent archive.

Focused production tests cover hash parity, unsafe JSON, original recovery eligibility, no-write cancellation/staleness, private import capabilities, post-preparation mutations, exact one-write fault outcomes and restart recheck, source equality, concurrent tabs and contended workspace/legacy locks, Complete/Duplicate admission, Trash/restored generation, owner removal/rotation, generic key boundaries and export exclusion. These are synthetic storage/lock tests, not proof of browser crash atomicity or a claim of a full/native suite pass.
